### R2-NEW-01 — HIGH — Local SDK drain does not fence or drain the host relay

**File:line:** `api/src/omnis/supervisor/model_sender.py:46–61,81–99,322–326`; `api/src/omnis/modules/runs/model_test_runtime.py:57–67,392–394,599–600,644–658`; `cli/src/omnis_cli/forwarder.py:90–110,349–409,491–504`.

**Actual failure path / reproducer:** The guarded write is into TLS-over-UDS. The separate host relay later does unguarded `destination.write(data)` to the provider TCP stream. Cancel/Revoke calls `drain_models`, cancels local tasks and closes only the SDK pool; no request/ack closes or proves quiescence of the relay's copy tasks, DNS thread, pending connect, or upstream connection. On local EOF, `_copy` half-closes upstream and `gather` still waits for the remote direction. During DNS, the relay can finish resolving and perform connect/`upstream.write(hello)` without checking whether that operation was canceled; `closing` belongs only to the forwarder process. A queued TLS body can likewise be forwarded after the local guard returned and cancellation committed.

Reproduce with the actual local relay and a synthetic TLS peer: hold its DNS/connect or outbound body-copy boundary after the SDK has handed bytes to UDS; Cancel/Revoke and read local FINISHED; release the held relay boundary and observe any new connect/write plus connection/task lifetime. Also challenge reused TLS. The existing PG fixture (`api/tests/test_model_test_v2.py:208–211,294–352`) terminates TLS directly at the UDS server and therefore does not traverse this production relay/queue. This is a concrete missing ownership/fence path; the timing observation remains NOT_RUN.

**Criterion:** Architecture §5 last-send/revoke serialization, STOPPING until local quiescence, §5.2 final veto at the actual send sink including reuse, §5.5 trusted dedicated channel. This does not assert remote inference can be canceled. Final CLI Stop does close/wait the relay process before its drained receipt (`forwarder.py:491–529`), but that later process shutdown is not a Cancel/Revoke relay-drain handshake and is not part of supervisor quiescence.

**Minimum remedy:** Extend the existing finite relay/owner protocol, not a general proxy: bind relay work/connections to the operation/epoch and revoke/drain acknowledgment, including queued bytes and DNS/connect ownership, before publishing quiescence. Ensure the authority boundary covers actual outbound writes, or explicitly enforce an equivalent fenced handoff. Add the one held-relay negative alongside a normal/reused-connection positive. Do not solve by weakening Stop semantics.

### R2-NEW-02 — HIGH — Truncation before redaction leaks credential material into observed metadata

**File:line:** `api/src/omnis/supervisor/model_sender.py:299–305`; supported key bounds `api/src/omnis/modules/settings/provider_vault.py:80–87`; public projection `api/src/omnis/modules/runs/model_test_runtime.py:165–188`.

**Actual failure path / reproducer:** A valid synthetic completion can echo the saved secret in `model` or `id`. The sender does `completion.model[:256].replace(secret, ...)` and the same for ID. With a supported 512-character synthetic secret echoed as the model, slicing leaves its first 256 characters; the full-secret replacement no longer matches. This prefix is persisted as `observed_model` and returned to web. A shorter secret straddling the cutoff also leaks its prefix. **Criterion:** Prompt §19–27 / architecture §5.4 bounded, sanitized provider output and no secret in public DB/API/UI. This is specific to raw exact-secret echo across the chosen bound, not a claim of universal DLP.

**Minimum remedy:** Redact the complete source field before applying its output bound; use the same order for ID and model. Add synthetic long-key and cutoff-straddling echoes through sender → persisted/public readback, with no real key.

### R2-NEW-04 — MEDIUM — Expected metadata transport failure permanently poisons the owner

**File:line:** `api/src/omnis/supervisor/model_sender.py:81–99,151–164,225–239`; `api/src/omnis/modules/runs/model_test_runtime.py:48–51,203–204,444–502`.

**Actual failure path / reproducer:** Explicit Refresh uses `sender.metadata()` directly, not the SDK's connection-error normalization. The custom transport passes through httpcore errors without mapping them to HTTPX; an absent/refused relay socket or malformed/EOF HTTP peer can raise a httpcore connection/protocol exception. `refresh()` catches only ValueError/OSError/TimeoutError (plus cancellation), not that transport exception. Its finally records a FAILED metadata result, but the task still fails and `finished()` permanently sets `settlement_failed=True`. Every later mutation, including an explicit fresh Refresh after transport recovery, returns CONTROL_UNAVAILABLE until process restart; `drain_models` also returns false. This conflates an ordinary provider/transport failure with failed durable settlement.

**Criterion:** A bounded failed/UNKNOWN provider attempt must remain readable and permit an explicit new attempt after local reconciliation; no retry, no permanent false drain/settlement fault from a handled transport outage.

**Minimum remedy:** Normalize the custom transport's expected network/protocol exceptions at its boundary, or catch that explicit taxonomy in metadata refresh, retain a sanitized FAILED result and complete the task normally after successful persistence. Reserve settlement_failed for actual settlement/control failures; do not blanket-swallow DB errors. Add one refused-socket/EOF Refresh followed by a healthy explicit Refresh, with no automatic network retry.
