# Omnis independent review and QA

## When to Use
Before accepting an implementation slice, resolving a regression, or declaring a phase delivered. Review functional compliance separately from code quality and visual approval.

## Procedure
1. Use `terminal` to identify base/head and `git diff`; include owned untracked files, relevant surrounding code and acceptance criteria. Establish existing failures without stashing someone else's work. A detached clean worktree can reproduce a baseline.
2. Apply `CONTRIBUTING.md` §„Execuție orientată spre produs”: requirement→consumer→risk→decision before a verification, without another admission report. Bind the product row, positive/negative controls on the same channel, exact commands and bounded budget. Before real QA use the existing runner's no-effect argv/choices/collect/source-library/access preflight and producer schema/oracle; declare the exact resource owner/cleanup and sanitized failure fields first. Require real-consumer QA on final bytes for a new or affected consumer, browser/E2E only for affected UI; do not accumulate helper approvals instead. Rerun affected tests after the LAST relevant edit. Full canonical is at the integration/phase boundary, not for every fix, Markdown edit or reminder. Missing evidence is NOT-RUN/BLOCKED; exit0 proves only the tested property.
3. Ask an independent reviewer via `delegate_task` for concrete findings: severity, file:line, reproducer, violated requirement, remedy. First ask whether the slice meets the spec; then inspect authorization, input boundaries, races, persistence, error handling and complexity. The reviewer is read-only in the shared checkout.
   Default to one author and at least one independent read-only reviewer on the frozen exact snapshot. Changes to authority, epoch, concurrency, model dispatch, Stop, effect/secret boundaries or cross-runtime contracts require two independent complementary reviewers on the SAME snapshot: (1) normative compliance/order/persistence/readback, (2) auth/concurrency/epoch/input/failure/accessibility/simplicity as relevant. Add an architect only for unresolved decisions/interfaces and a second developer only for real independent workstreams. After blocking findings clear, execute real-consumer QA when that consumer is new or affected; an independent reviewer may perform it under a separate QA contract, without a mandatory additional agent. An affected UI live review must open the built local app in a real browser and exercise clicks, keyboard/focus, reload and viewports against an owned API/DB; API/CLI-only reviews use their real consumer instead. Parent compares hashes and adjudicates results. Keep focused re-reviews on changed bytes and affected call sites, not another full-team pass for each fix.
   For a fix or pin/patch reseal, the manifest separates unchanged source from changed distribution. Unchanged behavioral approval remains within its original scope; it does not approve changed source or distribution. Require affected tests and focused re-review, plus parser/reapply/build and identity readback for the exact changed artifact. A helper/test finding does not automatically reopen unrelated reviewed requirements.
   Maintain a requirement→code→evidence matrix and an explicit disposition for every concrete finding from the original and later reports. A newer empty findings list does not close an older named reproducer: compare it against current bytes, and require RED→GREEN plus focused re-review for each surviving blocker before acceptance. A focused fix re-review closes its findings, not requirements that were never reviewed. Separate confirmed defects, incomplete proof and explicitly deferred scope; do not infer completeness from the last blocker being closed. Compare snapshot/scenario, not reused issue IDs, when a later review arrives.
4. Reject findings based only on style preference unless they conflict with a committed rule. Verify suspected bugs with a test. Fix blockers in minimal separate changes; rerun affected checks after the LAST edit. Two failed fix attempts trigger a narrower investigation, not blind repetition.
   Bound the review loop to the affected product acceptance criterion: re-review a concrete fix, not the entire growing harness. If two review/repair cycles advance only harness evidence without advancing that criterion, mark the slice WIP/BLOCKED and narrow the reproducer/reconsider the proof boundary before adding another process supervisor or mutation layer. Carry the cycles and dispositions for the same acceptance row across sessions; a new session or renamed oracle does not reset the count. New security findings remain separate explicit blockers. This does not approve unresolved findings.
5. For UI inspect the actual screenshot against the user's reference at agreed viewports. Test keyboard/focus, modal/drawer Stop, resize, loading/empty/error/unavailable, reduced motion, long content and real state transitions. Chromium smoke does not certify screen readers, all browsers or aesthetics.
6. Decide Reticle/Chisel applicability without ceremonial loading. For CLI/process/docs-only scope, report Reticle NOT_APPLICABLE and Chisel BLOCKED_NO_GO once; do not load either skill or rerun a tooling smoke. These are tools, not independent reviewers with opinions; never fabricate a second verdict from their presence. For executed applicable tooling, record scope/artifact, command, result and limitation.
   - Load `omnis-reticle` only for admitted, instrumented local UI runtime evidence; keep Playwright/DOM and screenshot checks independent. If the application is not instrumented, state NOT_INTEGRATED. A separately executed synthetic smoke is TOOLING_ONLY, not product acceptance, and need not be rerun for every finding. INCONCLUSIVE remains inconclusive. Do not install production instrumentation or use unrelated sites.
   - Apply Chisel's current NO-GO: BLOCKED_NO_GO on the repository/home/runtime profile until its adoption controls pass. Load `omnis-chisel` only for an explicitly authorized adoption reevaluation, using an exact artifact and OS-isolated disposable fixture; no unsandboxed fallback or automatic registration. Missing binary/probe infrastructure is NOT_RUN, not a fresh failure/pass measurement. Use native file tools while blocked.
7. Audit added lines and staged paths for credentials, sensitive evidence, unsupported dependencies and accidental files. Review generated changes against their source. Keep external revisions/licenses and actual failures in the change record.
8. Parent reproduces critical assertions and commits the accepted slice. Record exact commands, counts, exit codes, limitations and base/head; final reporting distinguishes implementation, integration and visual acceptance.
9. Use `omnis-project-status` for ORIENT before review and a scoped status delta at handoff. A read-only reviewer reports proposed changes; only the parent reconciles the map in CLOSE after adjudication. Bind approval to the reviewed snapshot/files, preserve genuinely open findings and compare delayed reports with later fixes. End with approved/in-review/not-reviewed or changes-requested scope, global gates and the next canonical slice; a review is not a runtime PASS.

## Pitfalls
For hash-routed prototypes, reload or create a fresh browser page between cases: fragment navigation retains run, dialog and filter state. Verify the isolated RED fails only for the intended behavior.

Verify focused pixels and target geometry, not only activeElement: an outer outline can be clipped, and a contextual link can preserve scroll below the selected object's title. Test repeat navigation from long mobile pages and place focus below persistent run controls.

Resolve an evidence/task link's operation, identity and snapshot explicitly; opening the destination page while retaining incompatible filters can display another object's evidence. Include a prior-selection/empty-filter regression.

Exercise rerenders as well as initial clicks: a stopped/paused run must not regain an active phase after finding review or filtering. Recheck current evidence availability in every consumer (finding, operation inspector, coverage and newly exported reports), while preserving historical verdicts and saved report snapshots. Download and parse the actual export; a preview count is not evidence that its bytes match.

No universal 'verified' badge. Challenge a verifier only for a concrete false-green defect or canonical acceptance obligation, not recursive report/harness audits. Match exact structured diagnostic identifiers/severity/source, not a substring in an exception stack; require positive and negative controls on the SAME evidence channel. An arbitrary failure or always-rejecting observer must not pass the negative control. Add a regression for a demonstrated false-green mechanism before trusting the repaired gate. A mock-only test or filename assertion cannot certify the product. Do not weaken safety or approve a review because it agrees with the implementer.

For a later-stage denial authored through YAML, keep earlier fields valid and preserve the intended literal type: quote all-digit hexadecimal pins and other string identifiers. An unquoted 40-digit pin becomes an integer and can hit INTEGER_LIMIT before the compatibility guard; that is not INCOMPATIBLE_HERMES evidence. Compare a real positive, the original encoding failure and the quoted identical literal on the same installed consumer before repairing the harness. Change encoding, not the identifier or expected reason; preserve the failed report and write the corrected run separately, without replaying unchanged product gates.

Measure an exact denial reason through the public parser or installed CLI before encoding it in an oracle. Trace exception inheritance and every enclosing handler: a callback's `CatalogError(ValueError)` can be caught and normalized to another public reason. Pair the same otherwise-valid integer control with wire and programmatic invalid inputs; keep those boundaries distinct, preserve refusal/state/replay assertions, and fix only the disproved expectation unless the product contract itself requires a separate change.

Test the producer of a safety flag as well as its consumer: injecting `uncertain=true` proves the cleanup predicate, not that signal exit, lost ACK or decoding failure actually sets it. Exercise the real failure boundary where safe, then pass its observed state into the cleanup oracle; label substituted daemon/resource seams rather than claiming an end-to-end effect.

For process-cleanup mutation controls, hold the synthetic child alive beyond the observed owner/reaper deadline unless an attested kill occurs, while arming a parent-death guard. Assert the actual `waitid` exit cause and bounded reap before crediting SIGKILL: a child's natural timeout can make a no-op kill mutant appear to pass. Rescue every pinned/adopted child and report UNCERTAIN on missing readback.

- Trigger a process signal test only after observing the intended owner phase (handler installed/worker admitted or a post-handshake marker), not an arbitrary delay from `Popen`: an early default SIGTERM can erase the receipt before the cleanup path runs. Keep the early-signal uncertainty as a separate negative, and never turn a missing receipt into PASS by sleeping longer.
- Before crediting an FD leak oracle, identify the descriptors it owns and quiesce any test peer whose accepted socket may close asynchronously. A global `/proc/self/fd` count can decrease between snapshots even when the product has not closed an owned FD; do not replace equality with a weaker `<=` assertion or infer the lost socket's owner without evidence.

When Hermes verify-on-stop names `make test`/`make check` but their prerequisites are unsafe or absent, report that canonical gate once as BLOCKED with the last relevant command, exit and limit. Focused checks remain targeted evidence even if the workspace ledger says unverified. Do not repeat them solely for the nudge or change the Makefile into a false-green alias; move to the prerequisite or stop the slice.

If a successful temporary verifier's own creation/deletion triggers another ad-hoc nudge, compare the tested source hashes once and retain its explicit nonzero test count and scoped PASS. Do not create a verifier for the verifier or replay unchanged checks to satisfy the ledger; continue the actual owned canonical gate separately.

For a read-only Python QA helper import, invoke the interpreter with explicit `-I -B` or set `sys.dont_write_bytecode=True` before the import: `-I` implies `-E`, so `PYTHONDONTWRITEBYTECODE` alone is ignored and can write `__pycache__` outside the owned scope. Include import caches in the write boundary; if a forbidden cache was created, preserve the artifact and execution FAIL rather than deleting it or replaying effects to manufacture a clean run. This controls Python bytecode writes only, not arbitrary native syscalls or helper side effects.

Treat private bootstrap/RPC receipts as secret-bearing even in a synthetic fixture: never return the whole file through `read_file` or serialize it into tool output. Parse privately and emit only the required nonsensitive field allowlist; for `runtime.boot`, a boot UUID is public evidence but `capability` is not. If exposure occurs, preserve the FAIL/incident and restrict the exact sensitive transcript; the parent must retire and verify the exact owned host/socket/family before an explicitly bounded fresh replacement. Do not reuse the exposed capability, overwrite the failed receipt, copy the transcript into Git, or describe a later clean run as undoing the disclosure.

For PostgreSQL pytest failures, treat raw tracebacks as secret-bearing too: default argument rendering can expose `database_url` even without `--showlocals`. Do not use `read_file`, context grep or a whole-log dump around an assertion; parse privately and emit only nonsecret test/exit/status/reason/count/settlement fields. Preserve the failed run and restrict owned logs; after exposure forbid fixture/credential reuse and verify exact endpoint retirement, without claiming that a later clean probe or private file mode undoes disclosure.

When rejecting private child stdout/stderr, keep raw bytes out of pytest assertion operands: assertion rewriting can interpolate them even in `--tb=line`. Preserve private output files and strict refusal, but raise only a sanitized reason through an explicit condition. Exercise empty-output acceptance and a synthetic nonempty marker refusal on the real pytest exception/line/short report channel; private file modes do not sanitize a rewritten assertion. This does not certify deliberate `--showlocals`/`--showargs` output.

For a confirmed host NSS path failure blocking a real audit or hash-locked dependency install, use the bounded [private NSS procedure](references/private-nss-audit.md). Keep helper review and targeted positives distinct from the canonical suite; do not change the host or bypass audit/hash results.

For exception-based test guards, record each attempted violation to an independent parent-owned channel **before** raising. Test a child that catches the exception and exits successfully: its report must still fail the clean verdict. Require observer readiness, known event tags and positive/negative controls; missing evidence is not zero attempts. Fail closed if recording fails, and distinguish Python audit events from native syscalls/OS confinement.

When typing a test observer/decoder, preserve unknown fields before leak/completeness assertions. A parser that strips unrecognized fields can manufacture a clean result. Exercise an unexpected synthetic marker at both top-level and nested payload positions, while rejecting wrong types; this evidence-preserving test policy does not replace strict allowlists on production inputs.

- Test teardown after an ordinary early driver exit, not only a live-driver timeout. A PPID snapshot taken after the leader exits loses reparented/detached children. Establish owned adoption or a managed scope before launch, exercise real SIGTERM-resistant children in both orderings, attempt all cleanup before exit-code assertions, and restore any per-test process attribute. Do not adopt preexisting/foreign work; publish final PASS only after teardown and parent-owned leak checks.
- In a signal/stop oracle, do not use a short child `sleep()` as proof the signal caused exit: under scheduler delay the child can finish naturally and return a misleading code before the observation. Hold a synthetic owned child on a parent-held pipe until the signal/exit assertion, close the release end in `finally`, and reap/kill only its verified process group if the assertion fails. An assertion after all CLI/browser children joined is a product/test failure, not automatically an uncertain writer; a PTY overflow/assertion **before join**, timeout or missing browser-close receipt remains uncertain even if a best-effort direct-child kill returned.
- For terminal-only secrets, treat the first attempted write through context-manager exit as one disclosure boundary: a writer may emit the whole code and then raise `ValueError`, `OSError` or `KeyboardInterrupt`, and a lock/finalizer can fail after `flush()`. Test each failure after actual bytes reach a TTY seam; never label it “not displayed,” retry issuance or echo the code in diagnostics. Keep pre-ACK denials distinct and test first-launch implicit `omnis` does not call the opener after uncertain disclosure.
- For private JSON lifecycle receipts, Python `True == 1` is not an authority check: require exact field sets/types (including socket identity lists) before Docker/HTTP attestation. Prove a valid READY receipt reaches the resource oracle, then mutate bool/unknown fields on the SAME installed start/status/pair/open channel and require refusal without code, browser or lifecycle effects.
- Test installed GUI outcomes as exact `(exit, origin, status, stderr)` tuples on **every** consumer, not a prefix or a success stdout paired with a contradictory failure diagnostic; a timed-out opener may have detached a browser and is `UNCONFIRMED`, not definite failure. Distinguish this consumer test from proving an OS window, and exercise a fresh non-TTY implicit launcher separately from fresh PTY/reuse with `pairing_issuance=0`, exact owned cleanup and data retained.
- At an installed CLI observer boundary, a joined direct child is not proof that its descendant family is settled after a signal or unrecognized positive exit (e.g. 99). Classify only documented normal exit codes before clearing `driver_uncertain` or the parent can publish a false cleanup. Contrast unknown exits with mismatched **recognized** normal exits, and label a parent-finalizer path inferred from code as such unless exercised end-to-end.
- Start a fresh finite resource-attestation deadline **after** an installed CLI has joined: a preflight deadline can expire while a valid slow startup uses its own bounded budget, creating false `UNCERTAIN`. Keep an unresolved CLI timeout/unknown child family uncertain; test the post-join boundary with a simulated startup beyond the initial observer budget and retain actual installed positive/negative controls separately.
- Before committing a reviewed fix, compare `git diff --cached --stat` and the relevant consumer hunk with each claim in the commit message. A helper's direct unit test does not prove every installed call site uses it; add a failing test at each missing consumer, then verify the staged file really changed. Correct an overstated commit explicitly in a later granular commit/note; never treat its prose as evidence.
- For SL04 Stop review, enumerate crash cuts on **both sides of every DB/journal commit and host effect**, including after Docker stop/rm but before the stage receipt fsync. A post-effect absence of a CID is not an ACK or proof that the effectful CLI family/daemon settled; demand a real recovery authority or retain `STOP_EFFECT_UNCERTAIN` and the physical cut as NOT_RUN.
- In retained-instance readback, compare the original data and current owner authority, not only a historical FINALIZE receipt, symlink/type/UID/mode, or a matching project label. Challenge an ordinary same-mode PGDATA directory replacement and a lease-epoch takeover on disposable fixtures; a synthetic query-shape check or fresh image boot cannot certify those properties.
- If a planned physical cut is vetoed by a live owned child, resume the paused pinned launcher and allow its normal bounded lifecycle to settle; do not terminate the owner just to exit the oracle, since that can create an unrelated STOPPING recovery. Mark the cut NOT_RUN, preserve its failed probe receipt, and read back any later *separate* owned recovery without retroactively promoting it.
- For a fixed-entrypoint owner, make authorization negatives reach the actual lock/identity guard with **valid argv arity and untrusted FDs**; wrong-argument refusal only tests the parser. Hold an ACK-emitting child live beyond the deadline under an independent test fuse: blocking `waitid(WEXITED)` after ACK never reaches a later `wait(timeout=...)`, and closing pidfd/pipe without bounded signal/reap may leak a child that still holds lifecycle locks.
- On malformed lifecycle receipts, test that schema denial precedes **both** normal and emergency effects: a READY validator's exception must not be interpreted as service outage that authorizes emergency teardown. Mutate exact types/field sets for STOPPING/STOPPED and verify status/pair/open reject legacy records before creating locks, contacting control or retaining stale `admission_open=true` in a failure projection.
- Strict fields are not sufficient for a lifecycle receipt: bind `instance.json` project/release/origin to the installed release/runtime receipt and current journal **before** offline STOPPED credit or an explicit Start's first Docker effect. Challenge a well-typed same-UID fixture with only project or release changed, and keep a valid matching control on the same installed consumer; a late comparison after `compose create db` does not prove pre-effect refusal.
- In offline lifecycle receipts, validate **domain transition arithmetic**, not only exact field types and plausible ranges: SHUTDOWN always increments generation, so a STOPPED receipt or correlated control reply with result equal to expected must refuse even when both reply/status agree. Put a matching positive and this negative through the same installed Stop/Status/Start and private UDS paths; an impossible receipt with absent CIDs must not become success without DB.
- Guard exact string type before set/dict membership on untrusted JSON lifecycle phases in every preflight/status consumer. A list or object can raise `TypeError` outside sanitized `StartError` handling; test both at real CLI entrypoints for exit 4, unchanged journal and zero lock/control/Docker effects rather than adding a broad `TypeError` catch that masks internal defects.
- Validate exact scalar types and database bounds at the service method before an idempotent replay branch, not only at IPC or INSERT: Python annotations do not reject `True`/`1.0`, and equality with a persisted integer can return an unauthorized successful replay without reaching SQL. Give reviewers both first-write and existing-receipt paths, each state, unchanged DB snapshots and the original valid replay; identity JSON must also survive storage round-trip without type normalization (reject floating-point resource identities rather than silently rebinding them).
- Require observed overlapping transactions when a review asks for concurrency: two sequential successful calls in opposite orders are not lock-wait evidence. Pause only after the actual product row locks, identify the owning PostgreSQL backend, observe its waiter through `pg_blocking_pids`, then release and inspect the state/result of both commands. Keep bounded cancellation/connection cleanup and state-injection coverage distinct from a real crash or ACK-loss producer.

- On a C10 lock/owner negative, prove the *actual owner* refuses before READY/ADMIT on the same exact payload as its positive. An observer withholding a gate proves only observer refusal. When the product protocol adds a required field, the raw old owner will reject the new schema before reaching the changed check; use a same-schema mutation of only the guard comparison and require that it reaches READY, while the stock owner denies the identical locked-independent OFD. Pin/reap both test-owned processes; a helper that reaps inside its Popen wrapper does not certify `run_stop_owner` cleanup.
- When duplicating a lifecycle lock FD before registering its `ExitStack.callback`, a BaseException during callback registration leaves the fresh alias and FLOCK live even though the stack unwinds older handles. Inject the first and second registration failures through the real Stop consumer on private roots, assert unchanged journal, closed guard FDs and reacquirable locks, and rescue only exact test-owned leaked aliases in RED. A failure of the second `dup` is a separate boundary and does not test callback registration.

- Before accepting a truncated or delayed review delivery, obtain the complete snapshot-bound report through a verifiable scratch JSON handle and read it back after the child completes. Missing text is not an empty findings list; persist the adjudicated verdict, concrete findings and limits in versioned slice notes before scratch expires. Do not poll a running child's transcript or report to wait for completion.

## No-rerun at a composed consumer

Trace replay/readback through pinned compiler and dependency validation before claiming no execution. A compiler may execute retained PURE qualification inputs; patching only the consumer's imported evaluator alias misses that branch. Observe the defining module and all invoked aliases, use a real dependency-bearing published snapshot, and either prove non-executing revalidation or explicitly refuse unsupported dependencies before that path. Keep the ordinary no-dependency positive; a blanket failure is not a replay proof.

## Installed QA scheduling and schemas

- Check the existing consumer's exact source/library prerequisites before spending a fresh PG/native attempt. A scratch source export can disappear between accepted slices; missing PIN/run_agent.py is a prerequisite FAIL, not a launch or product defect. Restore only the declared commit from a hash-matching archive, verify the original file inventory and overlay inputs without launch, preserve the failed attempt, and use a separately recorded fresh fixture. Do not substitute an unpinned installed/personal tree, prewarm imports or change product deadlines.
- Budget cold CLI startup and intermediate readbacks against immutable brief/stage deadlines. Run the positive admission promptly; put optional identity/input denials on a separate never-launched assignment rather than lengthening product grants or letting QA bookkeeping expire the positive.
- Compare exact named artifact inventories before asserting counts; resolve and deduplicate symlink aliases before counting physical artifacts. Native patched files and adapter modules are different sets. Stop a live proof after a failed preflight, preserve that failure and correct the observer before a bounded new attempt.
- Read the actual domain schema before asserting a native receipt field on a TaskResult or a flat steps field on a procedure; inspect its declared probe/baseline/control/cleanup groups. Validate the native cause and the domain gaps/method results at their respective records; an invented field must not motivate a product change, weaker oracle or replay of a successful consumer for report-only discovery.
- Transfer snapshot-bound reports from their exact original bytes, not reconstructed rendered read_file lines; long-string truncation/redaction can corrupt otherwise valid JSON. Use write_file on the exact source text and compare source/destination SHA, retaining the failed transfer without changing product bytes or rerunning its QA.

## Focused fixture and browser adjudication

- Trace native-root ownership to its physical uniqueness constraint before multi-input installed QA. Separate RUN contexts do not make one native boot/root reusable for multiple RUN bindings. Allocate a fresh owned boot/root per newly staged RUN; never relax uniqueness or product grants for the harness. Resource retirement does not retrospectively reconcile an old unbound stage.
- Keep catalog identity ownership consistent when qualifying variants of the same package in one private DB. An arbitrary new owner can hit IDENTITY_OWNERSHIP before a lexical refusal; use the legitimate same owner or explicitly distinct identities, then verify the intended frontier. Keep helper paths inside the actual owned TMPDIR required by their contract.
- For historical unstarted graphs, test exact readback/request replay and receive-only restart; reconcile without a native final result must refuse NEEDS_RECONCILIATION without writes. Do not invent a terminal result to satisfy an extra oracle. Byte equality alone is not an independent evaluator-call census.
- Attribute browser cancellations to measured request identity/action phase and same-browser successful readiness/pairing/session controls. Preserve cancellations and expected HTTP negatives; never hide unknown failures with a broad ERR_ABORTED exemption or describe expected errors as zero network errors.
- Distinguish full-page capture artifacts from live occlusion. Pair viewport/full-page images at identical scroll/focus, measure bounds and hit tests, and inspect actual pixels. Keep unpaired captures inconclusive rather than changing otherwise-working UI for the screenshot.
- When deliberately adding a supported wire version, inspect existing unknown-version controls. Add the new version to current-grant/transport positives and move only the obsolete unknown fixture to a genuinely unsupported version, preserving malformed-type, no-authority, no-resend and expiry assertions. Retain the original canonical FAIL; a synthetic peer proves transport only, not native admission.

- When a fix moves denial ahead of setup, keep the original regression but add a bounded late-sink control that actually reaches cleanup. Likewise, a worker joined only by the test finalizer does not prove it was drained before the product returned: observe the latched outcome and join boundary, challenge the after-poll interrupt window, and report timed-out cleanup separately from terminal denial. Do not replace these controls with a growing verifier framework.

## Verification
All named acceptance criteria accounted for, blocking findings resolved, regressions rerun and intended changes committed. Retained failures/limits are searchable in Git or concise versioned notes, not hidden in temporary transcripts.
