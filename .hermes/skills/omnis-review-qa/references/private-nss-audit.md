# Private NSS recovery for development-tool network prerequisites

Use only when the canonical package audit or hash-locked dependency install is blocked by the host's NSS resolver, not for an advisory, lock drift or package failure.

1. Use `terminal` for a bounded differential: normal `getent`/HTTPS and `getent -s dns`/`dig`. A working DNS answer with a stalled libc path localizes the prerequisite; a HEAD405 only proves transport, not an audit PASS.
2. Keep the pinned real audit binary. Use `write_file` to prepare a private scratch NSS file with only the `hosts` policy changed to `files dns myhostname`; preserve the other NSS database policies. Do not edit the host configuration or disable TLS verification.
3. Reuse the minimal reviewed network-only dispatch: exact first argv `audit` enters `exec unshare --user --map-root-user --mount --propagation private`, binds the private file onto `/etc/nsswitch.conf`, remounts it read-only, then `exec`s the real binary with quoted original argv. If a later cold installed-wheel dependency check fails, reproduce its exact locked command and network error before extending dispatch to `pip sync/install`; do not wrap runtime `run` commands or change the product test. Other commands remain direct, and product runtime UID stays outside the helper.
4. Use `terminal` to test real version/argv failure/nonzero propagation, an actual network audit and any newly routed hash-locked installer. Rerun the affected installed-wheel/migration test on a new owned fixture after extending dispatch; a warmed old venv alone does not prove it. Hash the host NSS before/after and all helper inputs; preserve stdout/stderr and limitations. Missing user namespaces or a mount failure is BLOCKED, never a fake audit or insecure fallback.
5. Request independent read-only review of the exact helper/evidence; keep it distinct from product review. Then pass the helper explicitly as the existing canonical audit-tool parameter and run one fresh serial owned fixture. Require the canonical receipt, source hashes and owned cleanup before crediting PASS; a separate successful audit does not certify the suite.

The namespace is not a general hostile-code or network sandbox. Canonical first-argument command shapes are supported, not global options before the subcommand. Namespace-visible UID0 maps to the invoking host UID; installer effects retain normal permissions. Trusted helper paths must remain unchanged through execution. Do not introduce a persistent daemon, global resolver change, dependency update or new generic harness to repair this prerequisite.

Verified Omnis example and complete helper bytes: `documents/verification/p1-web-a02-dns-v2.json`, with focused review in `p1-web-a02-dns-review-v2.json`; v1 is historical. Final canonical results belong in the slice register, not this procedure.
