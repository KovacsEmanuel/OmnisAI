# omnis-review-qa: postgresql-fixtures

Rețete tematice păstrate din procedura anterioară. Încarcă numai pentru frontiera concretă afectată; nu sunt preflight universal sau autorizație de efecte. Dovezile istorice rămân la reviziile lor.

For process-cleanup mutation controls, hold the synthetic child alive beyond the observed owner/reaper deadline unless an attested kill occurs, while arming a parent-death guard. Assert the actual `waitid` exit cause and bounded reap before crediting SIGKILL: a child's natural timeout can make a no-op kill mutant appear to pass. Rescue every pinned/adopted child and report UNCERTAIN on missing readback.

Treat private bootstrap/RPC receipts as secret-bearing even in a synthetic fixture: never return the whole file through `read_file` or serialize it into tool output. Parse privately and emit only the required nonsensitive field allowlist; for `runtime.boot`, a boot UUID is public evidence but `capability` is not. If exposure occurs, preserve the FAIL/incident and restrict the exact sensitive transcript; the parent must retire and verify the exact owned host/socket/family before an explicitly bounded fresh replacement. Do not reuse the exposed capability, overwrite the failed receipt, copy the transcript into Git, or describe a later clean run as undoing the disclosure.

- On a C10 lock/owner negative, prove the *actual owner* refuses before READY/ADMIT on the same exact payload as its positive. An observer withholding a gate proves only observer refusal. When the product protocol adds a required field, the raw old owner will reject the new schema before reaching the changed check; use a same-schema mutation of only the guard comparison and require that it reaches READY, while the stock owner denies the identical locked-independent OFD. Pin/reap both test-owned processes; a helper that reaps inside its Popen wrapper does not certify `run_stop_owner` cleanup.
- When duplicating a lifecycle lock FD before registering its `ExitStack.callback`, a BaseException during callback registration leaves the fresh alias and FLOCK live even though the stack unwinds older handles. Inject the first and second registration failures through the real Stop consumer on private roots, assert unchanged journal, closed guard FDs and reacquirable locks, and rescue only exact test-owned leaked aliases in RED. A failure of the second `dup` is a separate boundary and does not test callback registration.

Trace replay/readback through pinned compiler and dependency validation before claiming no execution. A compiler may execute retained PURE qualification inputs; patching only the consumer's imported evaluator alias misses that branch. Observe the defining module and all invoked aliases, use a real dependency-bearing published snapshot, and either prove non-executing revalidation or explicitly refuse unsupported dependencies before that path. Keep the ordinary no-dependency positive; a blanket failure is not a replay proof.

## Installed QA scheduling and schemas

- Revoke an incomplete multi-submit batch before releasing its original registry lock; an outer exception handler leaves a legal worker-access window. Prepare the full result set before publication and roll back interrupted publication under the same reader lock. Challenge the first unlocked cut through public result/status as well as batch readback; UNKNOWN registry state alone does not erase a previously published successful result. Preserve running futures and never equate revocation with drain.
- Require successful early-return branches to reach the shared strict observation gate after cleanup. Exercise the actual return/finally path with valid evidence and caught-forbidden/unknown-row negatives; assertions placed after finally are skipped by return. Preserve an already propagating failure/cancellation and the existing task-count checks rather than inventing a separate permissive oracle.
- Inspect the runner implementation before treating a flag as no-effect preflight. In `ops/run_test_db_gate.py`, `--check` provisions a private DB and runs the gate; use its grammar/`--help`, collection and static prerequisites for no-effect discovery. A familiar flag name is not evidence of dry-run semantics.
