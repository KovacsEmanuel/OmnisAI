# CLI P0.4 — status privat, bundle/imagine și forwarder host (launcher încă absent)

`omnis-cli==0.1.0` este un wheel separat, fără dependențe API/Hermes. `omnis status [--json]` citește un `instance.json` privat și interoghează `control.sock` cu peer UID + capability din directorul privat. Nu citește `.env`, nu caută checkoutul, nu contactează provider/ținte și nu pornește servicii. `control_ready=true` nu certifică HTTP/assets: `dashboard_ready=false`, `reason=HTTP_UNVERIFIED` chiar dacă supervisorul răspunde. `NOT_INSTALLED`/`CONTROL_UNAVAILABLE` nu adoptă un port străin și nu modifică fișiere. Coduri exit: 0 control verificat, 2 metadata invalidă, 3 absent/indisponibil.

Contractul provizoriu al metadata este `$XDG_STATE_HOME/omnis/instance.json` (implicit `~/.local/state/omnis`), 0600, director 0700, câmpuri `version=1`, `instance_id`, `release`, `schema`, `project`, `origin`. IPC este în `$XDG_RUNTIME_DIR/omnis`, sau în `runtime-ipc/` sub state dacă lipsește XDG runtime. Metadata și directoarele trebuie să fie private/canonice; `omnis install` instalează doar artefactele, **nu creează instanța DB sau `instance.json`**. Prin urmare, `omnis status --json` poate întoarce `NOT_INSTALLED`/exit 3 după instalarea bundleului: înseamnă „fără instanță înregistrată”, nu „fără fișiere de release”. Nu considerați `instance.json` sursă de autoritate pentru starea DB.

Pregătire explicită din repo, cu uv 0.12.19 / Python 3.13.15: `uv sync --locked --no-config --no-python-downloads --python 3.13.15 --directory cli`; `make check-cli check-release-install UV=/cale/uv-0.12.19`. Gate-ul verifică testele, lockul, Ruff/mypy și wheelul instalat într-un mediu scratch, plus bundleul real API/CLI/web. Instalarea CLI într-o locație de utilizator este explicită: `uv build --no-config --wheel cli --out-dir <scratch>` și `uv pip install --python <venv-cli>/bin/python --no-deps <scratch>/omnis_cli-0.1.0-py3-none-any.whl`.

**Bundleul local P0-control parțial:** construiește separat ambele wheeluri cu `uv build --no-config --wheel api --out-dir <scratch>/api-wheel` și `uv build --no-config --wheel cli --out-dir <scratch>/cli-wheel`, rulează `make build-web`, apoi exportă dependențele API cu `uv export --locked --no-config --directory api --no-dev --no-emit-project --no-header --no-annotate --format requirements-txt --output-file <scratch>/requirements.txt --quiet`. `OMNIS_UV=/cale/uv-0.12.19 cli/.venv/bin/python -I ops/build_control_bundle.py --api-wheel <abs-wheel-api> --cli-wheel <abs-wheel-cli> --requirements <abs-requirements> --web-root <abs-web/dist> --output <abs-bundle-nou>` compară exportul cu lockul API actual și produce `release.json` cu bytes checksum-bound, fără checkout în bundle. Dintr-un director extern, `<venv-cli>/bin/omnis install --bundle <abs-bundle>` copiază idempotent în `$XDG_DATA_HOME/omnis/releases/0.1.0` (implicit `~/.local/share/omnis`) și scrie `installed.json` 0600. `$XDG_DATA_HOME` trebuie să fie absolut/canonic sub un ancestor deținut de operator, fără segment înlocuibil/world-writable; directorul XDG lipsă este creat cu 0700 după verificarea ancestorului. Un alt release necesită upgrade explicit, nu overwrite. Instalarea nu migrează DB, nu descarcă imagini și nu pornește procesul.

**Imaginea API/control — probă explicită, nu deployment:** după `docker pull --platform linux/amd64 python:3.13.15-slim-bookworm@sha256:3e2de9c40ca4e3d73240059f9d48baff27908f10293e985a2f382a0378e6df4a`, `make check-control-image UV=/cale/uv-0.12.19` construiește exclusiv din bundleul instalat în scratch și verifică importul API/asseturile cu rețea oprită, root FS read-only și UID nonroot implicit/mapat; tagul probei este eliminat după readback. [Rezultate și limite](../documents/verification/p04-image-artifact.md). Buildul poate descărca numai dependențele fixate cu hashes de la registrul public, la această operație explicită, nu la `omnis` startup.

**Instalarea explicită a imaginii — încă fără servicii:** după `omnis install --bundle <abs-bundle>` și pullul explicit al imaginii de bază de mai sus, `<venv-cli>/bin/omnis install-image` construiește imaginea locală din releaseul verificat și înscrie `image.json` privat sub `$XDG_DATA_HOME/omnis`, cu ID-ul imaginii/proiectul, digestul manifestului, socketul canonic și identitatea daemonului Docker. La repetarea cu receipt valid se verifică ID-ul/labelurile fără rebuild și fără a cere încă imaginea de bază. Socketul trebuie să fie Unix pe o cale cu ancestori neînlocuibili; un `DOCKER_*` ambient este refuzat, iar același daemon este reverificat la readback. Bundleul este input local **de încredere al operatorului**: checksumurile lui atestă consistența internă, nu proveniența/semnătura independentă. Un build eșuat, un tag fără receipt confirmat ori un daemon indisponibil dau eroare/reconciliere manuală, nu succes optimist. `make check-installed-image UV=/cale/uv-0.12.19` probează în XDG scratch imaginea instalată exactă cu rețea oprită, root FS read-only și UID mapat, apoi face cleanup după ownership readback; [rezultate și limite](../documents/verification/p04-image-install.md). Nu face migrare, nu pornește PostgreSQL/API/supervisor și nu lansează un assessment.

**Topologie instalată — probă opt-in, nu `omnis start`:** bundleul include configurația trusted `ops/compose.yaml` pentru PostgreSQL/API/supervisor pe un bridge intern, **fără port Docker publicat**. API-ul răspunde pe socket Unix privat, iar `omnis_cli.forwarder` verifică peer UID și servește HTTP numai pe loopbackul host. `make check-installed-control UV=/cale/uv-0.12.19` instalează releaseul/imaginea într-un XDG scratch, migrează o DB PostgreSQL 18 disposable, pornește procesele din alt director, verifică schema lipsă 503/readiness/assets/IPC și un API instalat cu event loop blocat: Docker acordă 15 s, procesul părinte răspunde cu exit 4, iar o nouă pornire explicită reconciliază socketul privat. Gate-ul oprește numai resursele proprii și păstrează datele. [Proba actuală și limitele](../documents/verification/p04-host-uds.md) înlocuiesc pentru runtime [contractul static anterior](../documents/verification/p04-compose-contract.md). Gate-ul este explicit și folosește Docker local/imaginile deja pregătite; nu se declanșează la `omnis status` sau `install-image`.

**Nu sunt încă livrate:** pornirea/oprirea serviciilor **prin comanda `omnis`**, statusul HTTP legat de identitatea instanței, lockul de lifecycle/port și două launchuri concurente, pairing TTY, browser/open, stop/receipt, stop/start cu date păstrate și probele L01–L05/L08 complete. Topologia/UID din harness nu certifică aceste comenzi. `SO_REUSEADDR=False` refuză un port străin rezervat, dar propria conexiune în TCP TIME_WAIT poate amâna un restart pe același port; readback-ul după stop verifică absența listenerului, nu disponibilitatea imediată a portului. `make check` a trecut pe un [fixture DB disposable fără port Docker publicat](../documents/verification/p04-safe-test-db.md) la o revizie intermediară; gate-ul pe ultimul cod și checkout curat rămâne de rerulat, iar proba dintr-un peer LAN lipsește. Nu folosiți acest wheel ca serviciu operațional până la acele felii. Rollback cod: inspectați commitul și faceți `git revert`; releaseul copiat, imaginile, procesele și datele din afara repo-ului cer operații explicite separate; testele folosesc numai directoare scratch disposable.
