### Contractul feliei

1. Livrează **comanda reală, instalabilă `omnis stop`**, nu doar metode API sau un harness. Ea persistă tranzacțional intenția de shutdown și închide admiterea în `InstanceControl` (command ID idempotent, generație/fencing monotone) **înainte** de quiescență; folosește același lock local și bariera DB cu Start și celelalte admitări. Start concurent este ori deja inclus în stop, ori refuzat `INSTANCE_SHUTTING_DOWN`; nu există fereastră între quiescență și oprirea serviciilor. **Defectul moștenit SL03 este blocker SL04:** `shutdown`/`finalize` nu revalidează owner/epoch/lease după așteptarea lockului DB. Scrie RED pe PostgreSQL real cu lock-wait și înlocuirea/expirarea lease-ului, apoi verifică autoritatea în aceeași tranzacție înainte de FINALIZE/receipt/commit; owner stale refuzat fără publicație. Nu redeschide admiterea după un crash sau un simplu API reload.
2. Supervisorul/controlul privat atestat drenează lucrul inert și persistă dovada de quiescență înainte ca **numai launcherul host** să oprească exact containerele/procesele proprii, cu termene finite și readback. API/DB rămân disponibile până la persistarea rezultatului. Stop repetat este idempotent; păstrează volumele, DB și datele. Răspunsul controlului privat trebuie legat de **command ID, expected/result generation și epoch**: `local_control.py` citește acum status într-o tranzacție ulterioară, care poate aparține altei comenzi; un reply mixt nu autorizează `STOPPED`, teardown sau reopen. Cere readback DB + resurse exacte înainte de publicarea verdictului. Un ACK pierdut/timeout, ownership schimbat, proces cu familie necunoscută ori serviciu indisponibil rămâne `UNCERTAIN`/`RECOVERY_REQUIRED`, nu `STOPPED` fabricat. Calea de urgență cu API/DB inaccesibile încearcă să persiste și să citească înapoi un marker durabil `unreconciled` în state privat **înainte** de oprirea numai a resurselor identificate proprii; nu rescrie un run ca reconciliat în DB. Dacă și markerul este imposibil, eliminarea căilor de efect ale resurselor proprii poate continua pentru siguranță, dar rezultatul rămâne BLOCKED/UNCERTAIN (nu cleanup PASS), iar următorul Start este refuzat până la reconciliere externă; nu adoptă vechiul `admission_open=true`.
3. După stop verificat, **pornirea nouă explicită** (`omnis` sau `omnis start --no-open` conform contractului existent) verifică intenția/generația/quiescența/identitatea înainte de redeschiderea admiterii; nu face autoresume de assessment, model sau efecte. **Decizie de contract obligatorie înainte de cod:** planul §4.2 și matricea D02 numesc „comenzi stop/status/restart instalate”, în timp ce arhitectura §4.1 nu enumeră un subcomandă `restart` și §4.2 cere un Start explicit după stop. Propunerea KISS este probarea stop → `omnis start --no-open`/`omnis` → status drept restart explicit; documentează dacă această interpretare satisface deliverabilul planului sau cere aprobarea operatorului pentru un subcomandă definit. Dacă nu se poate adjudeca, marchează criteriul BLOCKED, fără a-l omite ori a inventa `omnis restart` pentru test. `omnis status [--json]`, pair/open și shellul existent rămân oneste pentru STOPPING, STOPPED, stale și RECOVERY_REQUIRED; fără secrete sau succes GUI inventat.
4. Refolosește lease/fencing, pairing/control privat, journaling și probele SL01–SL03. Corectează un defect de deadline numai după reproducer RED și fără a ascunde cleanup în bugetul startup.
