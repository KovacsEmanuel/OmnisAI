Impact & boundaries

In this synthetic scenario, Alice can read the contents of Bob's private test invoice despite an explicit deny rule. The example demonstrates one cross-account read — not access to every invoice, mass enumeration or a write capability.

Severity rationale: High because private billing data crosses an account boundary. No numeric CVSS or confidence score is invented.

Reproduction

Design walkthrough only. These steps and transcripts have not been executed.

  1. Restore the authorized preconditions

    Verify Alice's principal and role, the private test object, rule demo-rule-02 and a fresh isolated auth context.

  2. Establish the allowed baseline

    Read the shared test invoice as Alice. Match the expected object marker; a successful status alone is insufficient.

  3. Replay the private-object read independently

    The validator repeats the bounded GET for Bob's private test invoice. Compare the observed object marker with the expected DENY rule.

  4. Run the secure control

    The matching protected fixture must deny this private-object read while the shared-object baseline still succeeds. Auth failure alone cannot satisfy the control.
