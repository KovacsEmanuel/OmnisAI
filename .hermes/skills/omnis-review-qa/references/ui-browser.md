# omnis-review-qa: ui-browser

Rețete tematice păstrate din procedura anterioară. Încarcă numai pentru frontiera concretă afectată; nu sunt preflight universal sau autorizație de efecte. Dovezile istorice rămân la reviziile lor.

## Pitfalls
For hash-routed prototypes, reload or create a fresh browser page between cases: fragment navigation retains run, dialog and filter state. Verify the isolated RED fails only for the intended behavior.

Verify focused pixels and target geometry, not only activeElement: an outer outline can be clipped, and a contextual link can preserve scroll below the selected object's title. Test repeat navigation from long mobile pages and place focus below persistent run controls.

For a keyboard `:focus-visible` requirement after pointer actions, enter keyboard modality with a real Tab from a verified predecessor before measuring the ring. Programmatic `.focus()` can make the element active while `:focus-visible` remains false; a nonzero computed outline width with `outline-style:none` is not a visible ring. Reproduce the modality difference with current CSS and the pinned browser, retain the exact ring/geometry/target-size assertions, and distinguish a CSS-fixture proof from the fresh product journey. Do not weaken the oracle or change product CSS merely to satisfy a script-focus check.

For raw-CDP native disclosure checks, include generated text for character keys such as Space and wait for the browser's default action before reading `details.open`; a protocol ACK alone is not widget settlement. Persist the observed before/after state and raw geometry before an assertion, so an incomplete event or a misparsed CSS value cannot become a product bug or motivate a redundant React key handler.

For native closed `details`, do not equate nonempty `getClientRects()` with painted visibility: skipped descendants can retain layout rectangles. Pair a visible primary control and a hidden diagnostic control through native `checkVisibility()`/browser visibility plus viewport pixels; preserve the original observation and exact expected control/geometry assertions instead of changing product CSS for the observer.

When Hermes verify-on-stop names `make test`/`make check` but their prerequisites are unsafe or absent, report that canonical gate once as BLOCKED with the last relevant command, exit and limit. Focused checks remain targeted evidence even if the workspace ledger says unverified. Do not repeat them solely for the nudge or change the Makefile into a false-green alias; move to the prerequisite or stop the slice.

For PostgreSQL pytest failures, treat raw tracebacks as secret-bearing too: default argument rendering can expose `database_url` even without `--showlocals`. Do not use `read_file`, context grep or a whole-log dump around an assertion; parse privately and emit only nonsecret test/exit/status/reason/count/settlement fields. Preserve the failed run and restrict owned logs; after exposure forbid fixture/credential reuse and verify exact endpoint retirement, without claiming that a later clean probe or private file mode undoes disclosure.

- Test teardown after an ordinary early driver exit, not only a live-driver timeout. A PPID snapshot taken after the leader exits loses reparented/detached children. Establish owned adoption or a managed scope before launch, exercise real SIGTERM-resistant children in both orderings, attempt all cleanup before exit-code assertions, and restore any per-test process attribute. Do not adopt preexisting/foreign work; publish final PASS only after teardown and parent-owned leak checks.
- In a signal/stop oracle, do not use a short child `sleep()` as proof the signal caused exit: under scheduler delay the child can finish naturally and return a misleading code before the observation. Hold a synthetic owned child on a parent-held pipe until the signal/exit assertion, close the release end in `finally`, and reap/kill only its verified process group if the assertion fails. An assertion after all CLI/browser children joined is a product/test failure, not automatically an uncertain writer; a PTY overflow/assertion **before join**, timeout or missing browser-close receipt remains uncertain even if a best-effort direct-child kill returned.
- For terminal-only secrets, treat the first attempted write through context-manager exit as one disclosure boundary: a writer may emit the whole code and then raise `ValueError`, `OSError` or `KeyboardInterrupt`, and a lock/finalizer can fail after `flush()`. Test each failure after actual bytes reach a TTY seam; never label it “not displayed,” retry issuance or echo the code in diagnostics. Keep pre-ACK denials distinct and test first-launch implicit `omnis` does not call the opener after uncertain disclosure.
- For private JSON lifecycle receipts, Python `True == 1` is not an authority check: require exact field sets/types (including socket identity lists) before Docker/HTTP attestation. Prove a valid READY receipt reaches the resource oracle, then mutate bool/unknown fields on the SAME installed start/status/pair/open channel and require refusal without code, browser or lifecycle effects.
- Test installed GUI outcomes as exact `(exit, origin, status, stderr)` tuples on **every** consumer, not a prefix or a success stdout paired with a contradictory failure diagnostic; a timed-out opener may have detached a browser and is `UNCONFIRMED`, not definite failure. Distinguish this consumer test from proving an OS window, and exercise a fresh non-TTY implicit launcher separately from fresh PTY/reuse with `pairing_issuance=0`, exact owned cleanup and data retained.
- At an installed CLI observer boundary, a joined direct child is not proof that its descendant family is settled after a signal or unrecognized positive exit (e.g. 99). Classify only documented normal exit codes before clearing `driver_uncertain` or the parent can publish a false cleanup. Contrast unknown exits with mismatched **recognized** normal exits, and label a parent-finalizer path inferred from code as such unless exercised end-to-end.
- Start a fresh finite resource-attestation deadline **after** an installed CLI has joined: a preflight deadline can expire while a valid slow startup uses its own bounded budget, creating false `UNCERTAIN`. Keep an unresolved CLI timeout/unknown child family uncertain; test the post-join boundary with a simulated startup beyond the initial observer budget and retain actual installed positive/negative controls separately.
- Before committing a reviewed fix, compare `git diff --cached --stat` and the relevant consumer hunk with each claim in the commit message. A helper's direct unit test does not prove every installed call site uses it; add a failing test at each missing consumer, then verify the staged file really changed. Correct an overstated commit explicitly in a later granular commit/note; never treat its prose as evidence.
- For SL04 Stop review, enumerate crash cuts on **both sides of every DB/journal commit and host effect**, including after Docker stop/rm but before the stage receipt fsync. A post-effect absence of a CID is not an ACK or proof that the effectful CLI family/daemon settled; demand a real recovery authority or retain `STOP_EFFECT_UNCERTAIN` and the physical cut as NOT_RUN.
- In retained-instance readback, compare the original data and current owner authority, not only a historical FINALIZE receipt, symlink/type/UID/mode, or a matching project label. Challenge an ordinary same-mode PGDATA directory replacement and a lease-epoch takeover on disposable fixtures; a synthetic query-shape check or fresh image boot cannot certify those properties.
- If a planned physical cut is vetoed by a live owned child, resume the paused pinned launcher and allow its normal bounded lifecycle to settle; do not terminate the owner just to exit the oracle, since that can create an unrelated STOPPING recovery. Mark the cut NOT_RUN, preserve its failed probe receipt, and read back any later *separate* owned recovery without retroactively promoting it.
- For a fixed-entrypoint owner, make authorization negatives reach the actual lock/identity guard with **valid argv arity and untrusted FDs**; wrong-argument refusal only tests the parser. Hold an ACK-emitting child live beyond the deadline under an independent test fuse: blocking `waitid(WEXITED)` after ACK never reaches a later `wait(timeout=...)`, and closing pidfd/pipe without bounded signal/reap may leak a child that still holds lifecycle locks.
- On malformed lifecycle receipts, test that schema denial precedes **both** normal and emergency effects: a READY validator's exception must not be interpreted as service outage that authorizes emergency teardown. Mutate exact types/field sets for STOPPING/STOPPED and verify status/pair/open reject legacy records before creating locks, contacting control or retaining stale `admission_open=true` in a failure projection.
- Strict fields are not sufficient for a lifecycle receipt: bind `instance.json` project/release/origin to the installed release/runtime receipt and current journal **before** offline STOPPED credit or an explicit Start's first Docker effect. Challenge a well-typed same-UID fixture with only project or release changed, and keep a valid matching control on the same installed consumer; a late comparison after `compose create db` does not prove pre-effect refusal.
- In offline lifecycle receipts, validate **domain transition arithmetic**, not only exact field types and plausible ranges: SHUTDOWN always increments generation, so a STOPPED receipt or correlated control reply with result equal to expected must refuse even when both reply/status agree. Put a matching positive and this negative through the same installed Stop/Status/Start and private UDS paths; an impossible receipt with absent CIDs must not become success without DB.
- Guard exact string type before set/dict membership on untrusted JSON lifecycle phases in every preflight/status consumer. A list or object can raise `TypeError` outside sanitized `StartError` handling; test both at real CLI entrypoints for exit 4, unchanged journal and zero lock/control/Docker effects rather than adding a broad `TypeError` catch that masks internal defects.
- Validate exact scalar types and database bounds at the service method before an idempotent replay branch, not only at IPC or INSERT: Python annotations do not reject `True`/`1.0`, and equality with a persisted integer can return an unauthorized successful replay without reaching SQL. Give reviewers both first-write and existing-receipt paths, each state, unchanged DB snapshots and the original valid replay; identity JSON must also survive storage round-trip without type normalization (reject floating-point resource identities rather than silently rebinding them).
- Require observed overlapping transactions when a review asks for concurrency: two sequential successful calls in opposite orders are not lock-wait evidence. Pause only after the actual product row locks, identify the owning PostgreSQL backend, observe its waiter through `pg_blocking_pids`, then release and inspect the state/result of both commands. Keep bounded cancellation/connection cleanup and state-injection coverage distinct from a real crash or ACK-loss producer.
- Refresh the observer connection's local statistics snapshot before each `pg_stat_activity` poll in one transaction. Cached query text can hide a real waiter even while `pg_blocking_pids` sees the lock; prove the stale/fresh counts against an independently observed blocker, without `pg_stat_reset`, global settings, weaker predicates or wider deadlines. A synthetic-table reproduction establishes this mechanism, not the exclusive cause of an older product timeout.

- Check the existing consumer's exact source/library prerequisites before spending a fresh PG/native attempt. A scratch source export can disappear between accepted slices; missing PIN/run_agent.py is a prerequisite FAIL, not a launch or product defect. Restore only the declared commit from a hash-matching archive, verify the original file inventory and overlay inputs without launch, preserve the failed attempt, and use a separately recorded fresh fixture. Do not substitute an unpinned installed/personal tree, prewarm imports or change product deadlines.
- Budget cold CLI startup and intermediate readbacks against immutable brief/stage deadlines. Run the positive admission promptly; put optional identity/input denials on a separate never-launched assignment rather than lengthening product grants or letting QA bookkeeping expire the positive.
- Fence a dynamic DB fixture's destructive finalizer before launching a nested effectful child. Reuse the existing family owner and require its strict drain receipt plus authentic typed handoff before clearance; timeout, signal, unknown exit or exit0 alone retain uncertainty and the DB. Exercise the actual pytest finalizer order, since eventual outer drain cannot justify an earlier DROP.
- Place finite failure observation in the process that executes the affected code, before its exception normalization. A pytest-process NativePeer patch cannot observe a stock Host subprocess; a correlated Host refusal localizes that boundary but leaves its internal cause UNKNOWN. Preserve the original exception and uncertainty, capture only exact-code allowlisted fields, and do not expand the harness or alter grants from that partial diagnosis.
- For a cold launch/READY failure, emit bounded phase-entry markers and elapsed/audit counters in the existing observer before the suspected import/main boundary. Metrics emitted only after entry.main leave pre-main failures unobserved; reproduce that gap with code-object controls before another native attempt. Preserve last-entered versus completed phases, exact code/root filtering and incomplete evidence; keep fields sanitized without raw stderr, prewarm or wider grants. A marker localizes a boundary, not its cause.
- Serialize a threaded observer's cumulative limit check, real write and counter update together; a bounded record does not enforce the cumulative bound when `os.write` releases the GIL. Refuse same-thread reentrancy before acquiring a non-reentrant lock, and challenge the last slot with observed overlap and actual owned pipe writes.
- Require all finite pre-READY ENTERs and short-operation ENDs at the real consumer. Permit missing END only for explicitly named frames that span the RPC loop, retaining `INCOMPLETE`; a blanket missing-completion exemption can accept lost import evidence. Classify exact normal `SystemExit(0)`/`None` at the producer without copying arbitrary traceback categories, while preserving failure exits and unknown-input refusal.
- Compare exact named artifact inventories before asserting counts; resolve and deduplicate symlink aliases before counting physical artifacts. Native patched files and adapter modules are different sets. Stop a live proof after a failed preflight, preserve that failure and correct the observer before a bounded new attempt.
- Read the actual domain schema before asserting a native receipt field on a TaskResult or a flat steps field on a procedure; inspect its declared probe/baseline/control/cleanup groups. Validate the native cause and the domain gaps/method results at their respective records; an invented field must not motivate a product change, weaker oracle or replay of a successful consumer for report-only discovery.
- Transfer snapshot-bound reports from their exact original bytes, not reconstructed rendered read_file lines; long-string truncation/redaction can corrupt otherwise valid JSON. Use write_file on the exact source text and compare source/destination SHA, retaining the failed transfer without changing product bytes or rerunning its QA.

## Focused fixture and browser adjudication

- Resolve native select controls by their exact accessible combobox name when a label wraps the select and its options. Installed Playwright can return zero for exact `getByLabel('Provider')` while exact `getByRole('combobox', {name:'Provider'})` returns one. Prove the actual built App's post-navigation state before blaming Back; a tiny markup diagnostic establishes selector semantics only. Narrow text with a real locator such as `locator('small').getByText(...)`, not an unsupported `getByText` selector option silently ignored by JavaScript.
- Inspect passive notification placement against field labels and contextual hints, not only interactive hit targets. A toast can pass button-overlap assertions yet hide the field name. Pair actual viewport pixels with bounded geometry, keep44px/focus visibility, pause expiry while focused and resume remaining visible time after blur. For per-model progress, require that same operation to be pending; a shared Save busy flag is not evidence of model dispatch.

- Set Vite/Vitest cacheDir to an owned scratch path before using a shared node_modules symlink, or use private dependencies. A scratch-only source tree/symlink does not confine cache writes: result caches can land in the linked dependency tree. Preserve an observed scope violation instead of deleting or restoring a preexisting cache for a clean claim.
- Test reload/current-operation errors separately from post-command polling. QueryClient retains successful data after a failed refetch; a local-receipt-only unknown predicate can keep a secret-bearing challenge visible after reload. Require hiding on lost validity and recovery of the same operation without replaying Connect.
- For exact readback in an operator-paired browser without authorized debugging attachment, use an established receive-only local API route and the browser's native Save response into owned private scratch. First verify the route, response schema and data scope exclude credentials/private tokens; never export session endpoints, cookies, HAR, profiles or clipboard contents as a shortcut. Bind the saved JSON to the exact operation ID and requested snapshot before comparing usage/results: a latest-operation page can legitimately show another operation, and visual transcription alone is not byte-exact evidence. Preserve the native response; this readback does not count upstream calls or prove SENT.

- Trace native-root ownership to its physical uniqueness constraint before multi-input installed QA. Separate RUN contexts do not make one native boot/root reusable for multiple RUN bindings. Allocate a fresh owned boot/root per newly staged RUN; never relax uniqueness or product grants for the harness. Resource retirement does not retrospectively reconcile an old unbound stage.
- Keep catalog identity ownership consistent when qualifying variants of the same package in one private DB. An arbitrary new owner can hit IDENTITY_OWNERSHIP before a lexical refusal; use the legitimate same owner or explicitly distinct identities, then verify the intended frontier. Keep helper paths inside the actual owned TMPDIR required by their contract.
- For historical unstarted graphs, test exact readback/request replay and receive-only restart; reconcile without a native final result must refuse NEEDS_RECONCILIATION without writes. Do not invent a terminal result to satisfy an extra oracle. Byte equality alone is not an independent evaluator-call census.
- Attribute browser cancellations to measured request identity/action phase and same-browser successful readiness/pairing/session controls. Preserve cancellations and expected HTTP negatives; never hide unknown failures with a broad ERR_ABORTED exemption or describe expected errors as zero network errors.
- For visible inactive-tab QA, verify the native window/tab and actual `document.visibilityState` before crediting background polling. An automation-controlled browser can report both tabs visible/focused; preserve that observer failure and narrow to a dedicated native headed browser with raw CDP rather than changing the app or replaying Connect. A corrected visibility control does not recover a native operation that already became INDETERMINATE.
- Distinguish full-page capture artifacts from live occlusion. Pair viewport/full-page images at identical scroll/focus, measure bounds and hit tests, and inspect actual pixels. Keep unpaired captures inconclusive rather than changing otherwise-working UI for the screenshot.
- When deliberately adding a supported wire version, inspect existing unknown-version controls. Add the new version to current-grant/transport positives and move only the obsolete unknown fixture to a genuinely unsupported version, preserving malformed-type, no-authority, no-resend and expiry assertions. Retain the original canonical FAIL; a synthetic peer proves transport only, not native admission.

- Treat Python `-B` as write suppression, not a ban on loading existing bytecode. For an exact installed source closure, refuse unknown executable package caches before the first API import and again in each later fresh reader. Challenge an `UNCHECKED_HASH` cache added both before origin and after a successful origin; preserve the unknown bytes instead of deleting them for green. Keep trusted dependency/startup seams explicit rather than claiming a universal runtime audit.
- Compare the physical pytest `--basetemp` argument with the actual private `TMPDIR` before provisioning PostgreSQL/native resources. A selector can pin a global scratch basename that is outside a nested private TMPDIR. Configure only a fresh owned resource path through the existing selection seam; preserve the failed attempt and membership guard, without reusing the old basename or widening authority.
- Check a ZIP mutation factory's compressed output against the outer byte cap before crediting a member/aggregate negative. A newer valid wheel near the cap can make the factory fail before the targeted guard. Preserve that failure; if the resource guard is byte/AST-unchanged, narrow its controls to their original attested producer while testing the new real positive separately. Report the composed scope, not a fictitious one-command broad green, and do not raise the cap or add another verifier.
