## Contract nou bounded

RecordEnvelope rămâne schema_version=revision=1; payloadurile noi au `version:1`. `contract-case-input` conține exact `version,value,schema_ref,owner_id,context_ref,provenance`. `value` este obiectul validat de schema inputului, cu unicul câmp `capture`. Provenance este backend-owned `{producer_key: contract-case-input, producer_revision: contract-case-input-v1, command_id: UUID, source_kind: SYNTHETIC}`; revizia literală descrie protocolul, nu pretinde identitatea bytes a implementării. Closure-ul calificării include implementarea reală a validării.

`contract-input-context` conține exact `version,namespace,owner_id,basis_ref,snapshot_ref,procedure_ref,schema_ref,selection_ref,mission_ref,focus_ref`. În RUN, basis_ref este managed-run real, iar celelalte refs leagă snapshot/selection/mission/focus/procedură/schema exacte. În PACKAGE_EVAL, basis_ref este admiterea persistentă a candidatului exact; selection/mission/focus sunt null, nu UUID-uri fictive. Contextul de input nu este o nouă variantă de autoritate ExecutionContext și nu acordă acces tool/model.

`contract_inputs create-context` creează prefixul real mission/focus/metadata PromptBundle/managed-run/context; `create-input` primește context_ref și valoarea, produce și persistă inputul. Fiecare comandă este strictă, owner-locked și idempotentă; aceeași cheie/payload întoarce recordurile originale, alt payload conflict. Comenzile nu acceptă context/proveniență/IDs backend revendicate de client. `prepare-composed` păstrează schema1 fără slot; schema2 cere în plus context_ref și slot_values, exact un task/attempt și input admis pentru acel context. Refurile sunt reverificate la binding. Un context poate avea numai assignmentul inițial; alt assignment cere context nou. Inputurile sintetice imuabile nu primesc TTL inventat; disponibilitatea, namespace-ul, schema și eligibilitatea surselor se verifică la binding/admitere.

PACKAGE_EVAL este separat: admitere exactă a snapshotului înghețat → context/input sintetic persistente → PURE care rezolvă slotul → confirmare operator → Publish exact. Raw input fără admitere nu elimină UNBOUND_SLOT. Niciun run/copil nativ fictiv. Releaseul păstrează CASE_SLOT_REF, nu fixture-ul; RUN cere input nou în namespace propriu. Compiler/evaluator schimbate cer calificare nouă pe artefactul final, fără receipts istorice rescrise.

Schema și materialul nou de compoziție sunt versionate explicit (`composition_version=2`), distincte de compoziția1/wire v2 istorică și wire v1. Secțiunile rămân base, role, brief, method, apoi o secțiune nouă `{section: case-input, version:1, context: RecordEnvelope, input: RecordEnvelope, schema: {ref: Ref, document: object, path: Path, source_b64: Text}}`, apoi skills selectate. Schema păstrează bytes originali în source_b64; path/hash/size se leagă de fișierul manifestat al pachetului exact, nu numai de schema_ref cu digest de pachet. Subsetul strict este obiect cu additionalProperties=false, required=[capture], proprietate capture string cu maxLength integer și minLength opțional; fără $ref/pattern/DSL. Valoarea are maximum4096bytes UTF-8 pentru capture și8192bytes canonici agregat, schema originală maximum8192bytes; plafoanele graph65536/frame32768 rămân. Brief-ul citează metadata PromptBundle, niciodată invers. Secțiunea nouă consumă valoarea `value.capture`, nu numai ID/digest. Native verifică independent aceiași bytes înainte de constructor, inclusiv toate Ref-urile nested. Readbackul v1/v2 păstrează formatul și composerul istoric explicit admis; nu le reinterpretează drept compoziție2 și nu le transferă calificarea curentă.
