# omnis-hermes-runtime: sdk-preparation

Rețete tematice păstrate din procedura anterioară. Încarcă numai pentru frontiera concretă afectată; nu sunt preflight universal sau autorizație de efecte. Dovezile istorice rămân la reviziile lor.

- Attest live mounted state from the running container's mount namespace, not a Docker archive copy: `docker cp` may miss tmpfs contents. Use a finite, isolated installed-interpreter observer restricted to the exact synthetic paths; require unchanged file hashes and exact boolean marker absence, join the observer before family/drain checks, and retain a sensitive positive/negative control. Static installed source files can still be archive-attested separately.
- Renew actual stock-client authority immediately after successful launch, before blocking postlaunch census/observation; do not rely on a periodic task that has not yielded or extend the product grant to accommodate the harness. Register and checkpoint partial launch/renew/family evidence before an observer can refuse. A later successful run does not establish the cause of an older signal exit or reconcile its uncertainty.
- Keep credential-reader and native-runtime observation boundaries separate: an installed observer's store flags/modules and `/proc` initial environment do not prove the runtime's post-import memory, refresh behavior or loaded tools. Reverse `server_requests` advertisements are not a loaded-tool census. If a bootstrap registry is uninitialized/unobservable, retain NOT_INITIALIZED/NOT_OBSERVED rather than import/register/prewarm tools to fabricate an empty or complete inventory.
- Verify a proposed pre-run guard's actual veto semantics before using it as authority: the pinned `subagent_start` observer runs after child construction, omits an explicit batch index/manifest and swallows failures; execution middleware may fall through to downstream after an exception. Require an explicit indexed trusted sidecar and a fail-closed commit barrier before access, not association after `launch()` returns or a callback that merely logs failure.
- Establish NO_MODEL before native client initialization and conversation admission, not by cancelling a launched child, setting zero iterations or passing empty toolsets. At the pin, empty `allowed_toolsets` inherits the parent inventory. Keep installed preparation/loading evidence separate from native result/continuation evidence; neither a fake provider nor a deterministic emitter closes the latter boundary.
- Guard the public request entry before route selection, stale breakers and recovery, not only its worker constructor or shared sink: a stock pre-setup exception can otherwise escape NO_MODEL into credential/fallback handling. Keep a real open-breaker negative and the identical nonmanaged stock control; untrusted DTO refs and absence of an inert environment flag are not turn/config authority.
- Check exact inventory type before emptiness in a constructor-owned configuration observation: a nonempty tuple subclass can spoof equality with `()`. Require native tuple type before length, retain adversarial controls for both tools/toolsets, and never promote a genuine cold/null observation into READY provider-config or native-turn authority.
- Preflight effective non-root UID readability and directory searchability for every COPY artifact, including source, adapter, probe and manifest. Hash equality does not prove that imports can execute: preserve private modes with explicit owned COPY ownership rather than switching to root or loosening containment. Classify a pre-import permission exit as QA-driver BLOCKED/constructor NOT_RUN, retain that attempt and correct only owned distribution metadata before one bounded new consumer attempt; do not build another verifier.
- Trace a diagnostic launch seam through constructor-owned authority and final Stop predicates before using it in installed QA. `TestLaunch`/`TestPreparation` intentionally disable `namespace_owned` even at PID1; requiring certified STOPPED from that mode is unsatisfiable. Verify the actual caller and matching installed source; use the legitimate fixed-entry path rather than forcing the flag or weakening cleanup.
- Keep new diagnostic timer cancellation and each owned diagnostic FD close independently best-effort so observation cleanup cannot replace a primary exception or skip remaining cleanup. Separate pre-Stop process evidence from post-Stop signals; a signal first observed after Stop does not explain an earlier launch failure.
- Preserve the existing unified-patch framing, section order and unchanged sections when resealing a minimal native overlay; do not assume `diff --git` headers or regenerate unrelated context. Reconstruct only from attested post-inert originals, run `git apply --check` and apply in an owned copy, then compare the complete patched-file inventory and SHA values before publishing pin/manifest hashes. This keeps a distribution-only correction distinguishable from changed executable source.

## SDK-only preparation

- Treat extracted cache trees as insufficient provenance for original wheel hashes. Acquire only the explicitly granted lock URL/size/SHA closure, then install into a fresh private environment with offline, binary-only, hash-required copy mode; do not expand or update the closure.
- Check the pinned CLI grammar before consuming an installation intent: `uv pip sync` takes the requirements file positionally, not with `-r`. A parser refusal before installation is a QA-driver failure, not a product or SDK result; preserve it and reconcile the environment before a corrected distinct command.
- Exercise only the existing family runner's argument parser with the exact proposed argv before passing a namespace command containing standalone `--`. An embedded separator can be consumed by the outer argparse parser before the command starts; a missing family receipt remains UNCERTAIN. An exec-only argv wrapper may be proposed without replacing the owner or weakening isolation, but requires focused exact-snapshot review and real execution before credit.
- Keep full synthetic HTTP body bytes and request extensions when characterizing SDK serialization; digest/field-name output alone cannot show the model/messages/caps that were actually serialized. A capture-source stub proves driver retention only. No SDK execution means equality, extra_body behavior and namespace/seccomp controls are NOT_RUN, never inferred from installed metadata or static source.
- Stop after two QA-only repair cycles that do not answer the SDK question; hand off the concrete launch/consumer blocker rather than constructing a third audit. Record development-review traffic separately from forbidden product inference and verify leaf model/effort/Fast/approval settings before its first request rather than assuming delegate inheritance.

- Put extra SDK QA source copies beneath an already declared read-only mount, and resolve every source import against the exact bwrap destination map before consuming the attempt. A hash-verified host copy outside all mounts is still unavailable inside the sandbox; repair only the owned mapping/path, never expose a broader home or relax confinement.
- Keep lazy SDK platform metadata separate from the serialization oracle when it attempts `uname -p`: first preserve the actual denied audit event and source stack, then use a precisely tagged stock metadata negative control under active confinement before any create. Retain every event and require zero additional serializer IO; do not patch SDK/platform, fabricate headers, or call a cached-metadata measurement zero attempted IO at cold-start.
- Supply absolute control paths for leaf reports. A relative `implementation/...` can land in the repository instead of the owner's deterministic control directory. Preserve the scope deviation and relocate only exact newly created reports with a registered inverse and byte/hash readback; do not delete unknown files or transfer approval to changed product bytes.
Each G02/G04/G07 subgate has evidence at its actual boundary. Test restart, compression/lineage, duplicate events, wrong identity, stopped run and bounded outputs. Report live LLM tests as not-run until explicitly authorized and exercised.
