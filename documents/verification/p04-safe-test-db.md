# P0.4 — fixture PostgreSQL de test fără port publicat prin Docker

**Probă locală WIP, nu G00.** Fixture-ul anterior din `ops/compose.test.yaml` publica `127.0.0.1::5432` prin Docker 27; un bind pe loopback publicat de Engine <28 nu dovedește izolarea față de același segment L2. Nu am modificat daemonul, firewallul sau proiectele străine. Alternativa testată folosește imaginea PostgreSQL 18.6 fixată, `network_mode: host`, **fără `ports`**, cu `postgres -c listen_addresses=127.0.0.1 -c port=<port-sintetic-explicit>`. Aceasta este exclusiv baza disposable pentru gate-ul de dezvoltare, nu topologia API a produsului.

Înainte de startup: context Docker pe socket Unix local, toate controalele existente `/proc/sys/net/ipv4/conf/*/route_localnet=0`, portul ales neascultat, numele proiectului unic și niciun container/volum cu identitatea aleasă. URL-ul de test acceptă numai `postgresql+psycopg`, `omnis_test@127.0.0.1`, baza `omnis_test`, fără query/override `PG*` și cu portul explicit egal cu `OMNIS_TEST_DB_PORT`. Fixture-ul refuză mutanții de publicare Docker, proiect/port greșit, context remote, container privilegiat sau cu capabilități adăugate. Înaintea fiecărui `CREATE/DROP`, atestă din Compose și inspect ID/serviciu/proiect, imaginea fixată, volumul exact, `NetworkMode=host`, niciun publisher/PortBindings, `Cmd` cu adresa și portul fixate și identitatea `system_identifier` a clusterului conectat față de container. Testele sintetice de protocol sunt separate de proba live.
