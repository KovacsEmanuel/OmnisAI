01 / Concluzia principală

Omnis deține produsul.
Hermes furnizează motorul.

O platformă de pentest AI, controlată din web, este fezabilă. Calea recomandată este reutilizarea Hermes fără a transforma Omnis într-un fork masiv al unui asistent generalist.

Recomandare

Omnis separat + adaptor Hermes + plugin restrâns + execuție izolată. Păstrăm posibilitatea unui patch punctual sau a înlocuirii motorului, dacă experimentul arată blocaje reale.

Nu începem cu transplantarea autentificării, rebrandingul întregului Hermes sau un framework universal de agenți. Începem cu o singură investigație controlată, demonstrabilă cap-coadă.

02 / Fapte, nu presupuneri

Integrarea web are o bază reală.

Analiza s-a bazat pe propunerea Omnis, documentația oficială și inspecția selectivă a codului și testelor Hermes. Versiunea analizată: 0.21.5, commit ee5ee84a345204a3b1d6ef6ba1ab747e602867b9.

Hermes oferă deja HTTP, SSE, JSON-RPC și acces direct la clasa Python AIAgent. Nu trebuie să controlăm un terminal și să parsăm ieșirea lui pentru a construi o interfață proprie.[2][3]

Confirmat în sursă

  • Sesiuni, pornire de rulări și status.
  • Evenimente de progres prin SSE.
  • Stop, aprobări și intervenții în rulare.
  • Catalog de modele și pluginuri cu tools proprii.
  • Interfețe de administrare și anumite fluxuri OAuth web.

Încă nedemonstrat pentru Omnis

  • Funcționarea adaptorului cap-coadă.
  • Izolarea a două investigații concurente.
  • Blocarea tuturor rutelor în afara scope-ului.
  • Oprirea completă și recuperarea după crash.
  • Drepturile comerciale pentru fluxurile de abonament.

Limită a verificării: auditul a fost static. Nu s-au pornit servicii, executat teste sau scanări. Existența codului și a testelor nu echivalează cu o integrare Omnis validată.

„Totul din web” înseamnă două interfețe

Operarea agentului — mesaje, rulări, progres și rezultate — este diferită de administrarea instalării — provideri, autentificare, configurare, profiluri și skills. Dashboardul Hermes este o suprafață de management a mașinii, nu portalul unui engagement de pentest.[7]

În cod există fluxuri OAuth web, dar și intrări care cer un CLI extern. Prin urmare, o experiență Omnis din web este realizabilă, însă nu toate autentificările tuturor providerilor se transferă automat.

03 / Comparația opțiunilor

Integrare, extracție sau fork?

1.

Web Omnis peste un motor Hermes separat / Recomandat

Reutilizăm bucla agentului, modelele, skill-urile și mecanismele utile de sesiune. Omnis construiește engagementurile, autorizarea, investigațiile, dovezile și raportarea.

Nu este doar un wrapper de chat. Avantajul este că nu întreținem simultan un produs de pentest și o copie completă a infrastructurii generaliste de agent.

2.

Extracție selectivă / Utilă, cu limite clare

Copierea codului open-source nu este greșită. Presupunerea că un fișier mic este o componentă autonomă este problema. Pluginul Codex declară în esență providerul, tipul API și endpointul; nu conține întreaga autentificare sau execuție.

Contractul ProviderProfile spune explicit că nu deține construirea clientului, rotația credențialelor sau streamingul. Acestea atrag alte subsisteme.

3.

Fork masiv / Doar dacă vrem aproape întregul Hermes

Are sens pentru un produs care păstrează în mare parte experiența Hermes, dar o specializează. Este mai puțin potrivit când vrem o platformă de pentest care folosește numai anumite capabilități Hermes.

Un fork minimal este acceptabil. Dacă lipsește un hook necesar, un patch mic și testat poate fi pragmatic. Problema este divergența masivă, nu simpla existență a unui fork.

04 / Reutilizare fără transplant inutil

Ce păstrăm și ce construim noi.

ComponentăAlegerea inițială
Provideri și modeleRutare prin Hermes; Omnis stabilește modelele permise și bugetele.
OAuth și refreshUn singur gestionar al ciclului de viață al credențialelor; fără copii independente ale aceluiași grant.
Skill-uriFormat și conținut revizuit. Loaderul rămâne în runtime; metodologia se adaptează la tools Omnis.
SubagențiSarcini scurte de raționament, nu sursa de adevăr a campaniei.
ProfiluriConfigurații de runtime, nu utilizatori sau granițe de tenant Omnis.
SesiuniHermes pentru conversație; Omnis pentru starea investigației.
UI și brandingFrontend Omnis propriu. Nu este necesară preluarea UI/TUI Hermes.
Scope, dovezi, findingsResponsabilitate Omnis. Autorizare, audit, validare și raportare.

Autentificarea nu este un loc bun pentru copy-paste superficial

Refresh-ul Codex folosește o tranzacție care acoperă recitirea, refresh-ul și persistarea tokenurilor. Aceasta evită folosirea concurentă a tokenurilor deja rotite. Nu aș face din Omnis și Hermes doi gestionari independenți ai aceleiași autentificări.

Skill-urile sunt mai portabile decât infrastructura lor

Un SKILL.md poate presupune anumite tools, scripturi, căi, programe și credențiale. Aș reutiliza metodologia și aș adapta interfețele; nu aș importa întregul catalog cu libertatea de a instala orice dependență cerută.

Licența codului și dreptul de acces la servicii sunt lucruri diferite

Licența principală verificată este MIT, cu păstrarea notificărilor relevante. Există și componente cu alte atribuiri și licențe, inclusiv cod Apache-2.0 în pluginul security-guidance. Nu a fost făcut un audit complet al dependențelor și asset-urilor.

Hermes documentează autentificare prin anumite abonamente, dar condițiile diferă între provideri. Funcționarea tehnică în Hermes nu demonstrează dreptul de redistribuire a accesului sau utilizare într-un SaaS multi-user.[5]

Alternativă pentru mai târziu: doar inferența prin proxy

Există un subscription proxy, diferit de API-ul agentului. Poate fi relevant dacă Omnis ajunge să aibă propria buclă de agent și are nevoie numai de acces la model. Proxy-ul nu aduce skills, memorie sau execuția uneltelor și nu presupunem că suportă orice provider. Nu trebuie expus direct unui public neautentificat.[9]

05 / Arhitectura recomandată

Motor înlocuibil. Control propriu.

Frontendul vorbește cu Omnis. Hermes rulează separat, cu unelte restrânse. Efectele asupra țintelor trec obligatoriu prin brokerul Omnis, care verifică acțiunea concretă.

Pluginul poate oferi consultarea contextului, solicitarea unei acțiuni HTTP, citirea dovezilor redactate și propunerea de ipoteze. Hermes permite înregistrarea acestor tools fără modificarea nucleului.[4]

Pluginul nu este executorul privilegiat. Brokerul verifică autoritatea asociată rulării, nu un identificator de engagement inventat de model.

Hermes deține: model → tool → rezultat → următorul pas.

Omnis deține: engagement → task → autorizare → dovezi → validare → raport.

Monolit modular, nu microservicii peste tot

Frontend propriu, backend modular, PostgreSQL, stocare de dovezi și runtime/executor separat unde izolarea o cere. Fără Kubernetes, framework universal de agenți sau bază de date de graf separată din prima versiune.

06 / Limite care schimbă designul

Ce nu trebuie confundat cu o garanție.

  1. O opțiune Python nu este automat un câmp HTTP.AIAgent oferă mai multe opțiuni decât expune calea API obișnuită. Toolseturile provin din configurația profilului/platformei. Adaptorul trebuie construit după contractul efectiv.
  2. Un hook nu este singurul firewall de scope.Middleware-ul poate continua către execuția normală după eroarea unui callback. pre_tool_call poate bloca la excepție sau timeout, dar există și fallback exterior care continuă la eroarea infrastructurii de dispatch. Controalele nu au toate aceeași semantică.[6]
  3. Profilul nu este un sandbox.Hermes are multiplexare și separare software de configurație/secrete. Acestea nu creează automat UID-uri, rețele sau filesystemuri inaccesibile reciproc.
  4. stopping nu înseamnă „toate efectele au încetat”.Stop solicită întreruperea și încearcă să curețe procesele asociate. Omnis trebuie să revoce acțiunile noi și să verifice terminarea executorului. O cerere deja ajunsă la țintă nu poate fi anulată retroactiv.
  5. Lista configurată nu este întotdeauna inventarul final.Pluginurile, serverele MCP, rezolvarea toolseturilor și rolurile copiilor pot modifica suprafața disponibilă. Verificăm efectiv uneltele vizibile, inclusiv după upgrade.
Modelul poate propune și adapta. Codul autorizează efectul. Dovezile susțin findingul.

Nu atașăm un hook peste un shell nelimitat și declarăm că avem scope enforcement. Verificarea trebuie să existe în calea obligatorie a efectului, completată de restricții OS/rețea.

07 / Critica propunerii existente

Direcția este bună. Prima versiune trebuie restrânsă.

  1. Agentul restrâns înaintea dashboardului bogat.Întâi demonstrăm că Hermes păstrează raționamentul util când poate produce numai efectele oferite de Omnis. Abia apoi investim în multe pagini și vizualizări.
  2. Mai puțini agenți la început.Coordonator, recon, tester, validator și reporter sunt responsabilități, nu obligatoriu procese distincte. Începem cu un investigator și o etapă separată de validare.
  3. O singură sursă de adevăr pentru fiecare tip de stare.Omnis deține politica și snapshotul rulării; Hermes gestionează mecanica runtime-ului. Nu duplicăm cataloage manuale și mecanisme OAuth care trebuie sincronizate permanent.
  4. Izolarea și oprirea intră în primul experiment.Multi-tenancy complet poate aștepta. Blocarea ieșirii din scope și oprirea efectelor nu pot aștepta până după MVP.
  5. Model de date înaintea grafului vizual.Suprafață → observație → ipoteză → test → dovadă. Un graf frumos nu compensează findings fără suport.
  6. Al doilea model oferă o opinie, nu o dovadă.Validarea folosește controale și rezultate observabile. Unele cazuri de logică de business cer review uman. Rezultatul poate rămâne neconcludent.

08 / Fezabilitate demonstrabilă

Un experiment mic trebuie să decidă investiția mare.

Ținta realistă: un produs intern pentru Web/API autorizat, cu investigații autonome limitate, operare din web și raportare bazată pe dovezi.

Nu avem încă suport pentru promisiuni de pentest complet asupra oricărei aplicații, autonomie nelimitată, zero false pozitive, SaaS ostil izolat prin profiluri sau folosirea oricărui abonament pentru oricâți utilizatori.

ProbăCriteriul de trecere
Control programaticSesiune, run, progres, rezultat și stop fără parsarea terminalului.
Capabilități restrânseAgentul și copiii văd numai uneltele aprobate, inclusiv după rezolvarea pluginurilor/MCP.
IzolareDouă investigații nu amestecă stare, credențiale sau dovezi.
ScopeO destinație nepermisă și un redirect către ea sunt blocate tehnic.
Oprire și recoveryOprirea revocă acțiunile noi; după crash nu se repetă orbește o acțiune cu rezultat necunoscut.
Valoare realăUn caz vulnerabil este demonstrat, iar controlul sigur nu devine finding.

Când schimbăm recomandarea

  • API-ul și pluginul sunt suficiente→Păstrăm Hermes separat.
  • Lipsește un control punctual→Adaptor Python în worker sau fork minimal.
  • Restrângerea sigură cere modificări în multe subsisteme→Reevaluăm extracția sau runtime-ul propriu.
  • Produsul dorit este aproape integral Hermes specializat→Fork-ul masiv devine o alegere explicită.

Nu alegem între „de la zero” și „copiem tot”.

Omnis poate fi un produs integral propriu pentru utilizator, cu Hermes în interior. Păstrăm controlul asupra permisiunilor, efectelor și dovezilor — fără a moșteni toate funcțiile active ale unui asistent generalist.

Ipoteza inițială recomandată: o singură organizație, echipă autentificată și ținte Web/API controlate. Decizia care schimbă cel mai mult arhitectura este dacă aceasta este prima versiune sau dacă urmărim SaaS pentru clienți diferiți încă de la început.

09 / Trasabilitate

Ce susține concluziile.

Documentul reformatează concluziile analizei din conversație. Nu aprobă implementarea și nu înlocuiește un test operațional, un audit complet de securitate sau verificarea contractuală a providerilor.
