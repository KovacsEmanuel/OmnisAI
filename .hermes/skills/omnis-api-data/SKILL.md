# Omnis API and persistence

## When to Use
P0/P1 and later FastAPI endpoints, domain state, SQLAlchemy models, Alembic migrations, SSE or evidence metadata. Not for changing the stack by preference.

## Prerequisites
Read the active architecture, relevant ticket and stack pins. Inspect actual manifests before commands: the application may still be unimplemented. Keep API, Hermes and proxy dependency environments separate. Use `terminal`, `read_file`, `write_file`, `patch` and `search_files`.

## Procedure
1. Name the domain invariant and owning transaction before defining a route. Separate HTTP validation, domain decisions and storage; use typed Pydantic DTOs with explicit state/error enums. Do not expose ORM objects as an accidental API.
2. Write an integration test with synthetic data for the desired behavior and its denial/invalid-input control; demonstrate RED. Validate boundary input, authorization, Host/Origin/CSRF and local bootstrap policy where relevant.
3. Implement only the required transaction. Use optimistic concurrency and a real 409 test for concurrent edits; run/task revisions, evidence state and event sequence cannot be owned by a React cache or Hermes conversation.
4. Add the migration with the feature. Test an empty PostgreSQL database and upgrade from the previous revision. SQLite is not proof of PostgreSQL behavior. Inspect the actual image's PGDATA/mount contract, not a remembered older major.
5. For idempotent commands test duplicate/reordered delivery and competing writers. Use a transactional outbox/durable event contract only where the architecture requires it; SSE cursor replay must agree with canonical persisted state after restart.
6. For evidence writes test the file/DB finalization protocol, partial writes and crash windows; render untrusted content inertly. Bound raw, decompressed and retained bytes separately. Do not use the trusted-doc renderer for target data.
7. Generate frontend types from the local Omnis OpenAPI contract when introduced; verify drift in CI. Exercise the real route via HTTPX/ASGI plus database integration, not a mocked repository returning the expected answer.
8. Run targeted tests then the affected suite, type/lint checks and migration probes. Use the committed commands actually present in the component manifest. Document data migration rollback limitations, not merely `git revert`.

## Pitfalls
Do not swallow exceptions, retry uncertain external effects as if they were safe, return success for queued completion, or weaken validation to satisfy a linter. An in-memory smoke is not durability; a restart test must restart the owning process and read real state.

- Cross-check a new persistent record against its base domain schema as well as the specialized wire/result contract before emitting it. Include every mandatory field and bound in producer and readback validation; a valid native envelope can still omit required CriterionOutcome fields from architecture §9.3. Pair a genuine stored positive with missing/malformed-field refusal before equality, without rewriting immutable historical records.

- At an explicit receive-only reconnect, normalize only anticipated filesystem/metadata/transport failures at that boundary into the existing sanitized indeterminate exception after cleanup. Exercise original-Host disappearance through the real owner and private control UDS: an uncaught FileNotFoundError can produce EOF and an asyncio traceback with a private filename even when no work is authorized. Preserve cancellation/internal errors and forbid reconnect-and-resend or replacement-Host fallback.

- Obtain newly required data from compact assignments through the existing strict, ref-bound expansion after validating constructor-owned bytes; never assume an inline field also exists in the compact wire payload. Exercise the actual producer-to-caller path with compact and inline controls, including supported historical pins: expanded-only state holders can pass while the real caller fails after read/tool effects. Preserve caps, receipts and code-identity boundaries; a helper approval does not certify the changed caller.

- Before a database record cites newly created filesystem material, flush the containing directory namespace bottom-up through the material root and its parent. A file fsync or immediate-child fsync does not persist the parent's new root link; exercise a new-root positive with real delegated fsync, and keep physical power-loss NOT_RUN unless actually probed.
- Bound derived collections before capturing or reserving anything, using one shared limit at both the request and real material helper. A package cap must reserve capacity for the mandatory profile in the later source-ref budget; prove the exact maximum remains reviewable/rejectable and the next package refuses before filesystem reads. Generated refs at a validator seam are not persistent-DB evidence.
- Derive an immutable qualified artifact's dependency graph from every retained input used by its qualification, including its profile, not only exported package templates. Prove qualification-to-consumption round-trip with a profile-only transitive RELEASE edge and exact missing/undeclared-pin denials; keep reachability, declared-edge equality, cycle and shadow checks rather than removing them to admit a valid fixture.
- Before adding an immutable artifact's next consumer, inspect the producer's source-byte fingerprint closure: an entrypoint or storage edit can change compiler/evaluator identity even when the algorithm is untouched. Prefer a separate consumer seam when appropriate, and qualify a fresh owned fixture on the final artifact before promoting its exact snapshot. Do not remove trusted files from the closure, force a revision literal or rewrite old receipts to transfer PASS; retained-snapshot compatibility/upgrade requires its own real consumer proof.
- When adding a migration, inventory schema pins in every real consumer and artefact builder, not only API readiness and migration tests: CLI instance/release/start, bundle metadata and fresh positive fixtures must agree on the new exact head. Preserve historical revisions, intentional old-schema denials and retained releases; prove the affected PostgreSQL consumer and upgrade transaction rather than accepting both heads or rolling out over an existing instance.
- Reject U+0000 in every authored string destined for PostgreSQL JSONB, including nested list items, before a Save transaction. PostgreSQL rejects it after DTO acceptance and otherwise turns invalid input into a misleading 503; exercise the real HTTP field error and a valid control on the same route.
- For an exact origin stored separately from its port, reject an empty port delimiter explicitly: `urlsplit("https://host:").port` is `None`. A `port is None` check alone accepts ambiguous scope data; test the negative and a valid origin through the same API.
- After adding shared Pydantic `Annotated` validators, compare two fresh-process OpenAPI exports byte-for-byte before trusting contract drift checks. A PEP 695 `type` alias combined with field metadata can embed runtime identity in `$ref` names; use a stable alias assignment when needed, then regenerate OpenAPI/TS from the source.
- Compare the Cartesian maximum of individually valid DTO fields with the route's wire-body cap before claiming a maximum-size Save. Declare a separate bounded aggregate payload budget in the DTO/OpenAPI if needed, then test the same authenticated route at positive large-context readback, sanitized 422 below the wire cap and 413 above it; never widen the Pairing/global boundary to make a draft pass.
- Before fixture CREATE/DROP, use the shared private-manifest attestor: exact local daemon/CID/image/project/binds/UID/no-network/UDS, then compare the **connected PostgreSQL system identifier**. Keep the encoded URI in fixtures and decode only at the engine or explicit driver kwargs; serializing an already-decoded Unix host loses URI authority. Reject query/PG overrides, noncanonical paths and commas (libpq multi-host semantics) before connection. Never adopt an existing DB or fall back to TCP; re-attest before migration and teardown.
- A migration *failure* test must not send a valid DSN to an arbitrary fixed port hoping the connection fails: an unrelated DB there could accept it and receive DDL before the assertion. Exercise wrong-password failure on an attested UUID-named disposable DB; for config denials use inputs rejected before socket I/O. Re-attest ownership immediately before a long build-to-migration handoff.
- On PostgreSQL 18, `attnotnull=true` can coexist with `NOT NULL NOT VALID` and existing NULL rows. A compatible-schema probe must compare the exact authority column/**every default**/constraint set including `pg_constraint.convalidated` and `conenforced`; a revision stamp, partial default map or subset check can report a false ready. Exercise the real DDL mutation on an isolated DB before trusting the negative test.
- Bound connection, lock and statement waits **and the downstream coroutine** for every DB-backed HTTP operation. A PostgreSQL statement timeout does not bound a stalled client connection. Fault-inject a stall after a real transactional write; require bounded sanitized failure, rollback readback and no success cookie. Keep test subprocess deadlines finite.
- Preserve one-use issuance as well as consumption: retain an immutable receipt binding issuance ID, digest and original expiry. Replay after consumption, supersession or expiry must neither reactivate a code nor extend its TTL; a fresh ID must not reuse the same code. Commit failed-attempt counters before raising denial, and check expiry with current DB time after acquiring the lock.
- A private issuer's initial owner/lease check is not authority through a later blocking challenge-row lock: recheck the same pinned owner/epoch with PostgreSQL's current time **after** the wait and before transaction commit, so an already expired lease rolls back both challenge and issuance receipt. Prove it with a real locked disposable DB row, an observed successful first check, real DB-clock expiry, and a rollback readback; a short production statement timeout may hide this race by failing earlier, so any test-only `SET LOCAL` timeout extension must be labeled and must never change production admission limits. A pre-commit clock check does **not** prove that the lease remains valid at the physical commit timestamp; do not claim that stronger invariant without a separately specified protocol and oracle.
- A row already selected `FOR UPDATE` can still wait later at `UPDATE`: PostgreSQL `SHARE` table lock permits the SELECT's `ROW SHARE` lock but conflicts with UPDATE's `ROW EXCLUSIVE`. Recheck owner/epoch/lease with DB time after the UPDATE in the same transaction before publishing quiescence; test with that real table-lock ordering, expiry during the wait and rollback readback on a disposable PG fixture. A fixture-only extended statement timeout is not a production deadline change or proof of authority at the physical commit timestamp.
- Establish listener ownership, inode and permissions before an asynchronous serving call can yield. On the pinned Python, create a non-serving Unix server first, then start serving; inject cancellation at the first yield and verify the listener is gone and restart succeeds. A successful normal shutdown does not cover partial startup.
- When typing SQL results, validate driver values into strict records/scalars rather than casting dynamic values. Strict Pydantic models may reject `RowMapping` even when its fields are correct: normalize only the Mapping container to a dict, preserve every field, and retain strict value checks. Prove acceptance on real driver rows and rejection of coercions; sanitize validation failures as storage failures, not invalid client requests.
- Test cancellation together with a transport-close failure. A `return` inside cleanup can erase the original exception; suppress only the expected close error without returning from `finally`, and require the original cancellation to propagate.
- Keep health/status observation separate from authority renewal. Inspect the entire reused IPC handler, not only its command name: a status dispatch may call heartbeat. Reproduce with PostgreSQL expiry readback, continue polling across expiry without the owner loop, and require the lease to expire unchanged; validate owner/epoch without extending it.
- Require container-local TCP health for the final PostgreSQL server when the image initializes through a temporary Unix-only server. Prove the distinction with a fresh owned PG18 init marker: Unix pg_isready may exit0 before init completes while localhost TCP refuses, then the same TCP health must pass on the final server. Keep ports unpublished and the network private; pg_isready proves connection admission, not authentication/schema/identity. A phase spike does not establish an unrelated historical command failure or certify the installed bundle; rebuild and run its canonical gate separately.
- At service entry, validate exact authority argument types/ranges before the idempotent replay lookup. Python `True == 1` and permissive driver coercion can turn an invalid revision into the original successful receipt; test the real PostgreSQL first-write and existing-receipt paths with invalid types and a valid replay control.
- Strict DTOs cannot detect duplicate JSON members once FastAPI has decoded the body. For versioned draft writes, reject duplicate keys recursively on the already bounded, authenticated body before DTO parsing; exercise top-level and nested duplicates through POST/PUT plus a valid control, without weakening Host/Origin/session/CSRF or Pairing limits. An escaped unpaired surrogate may already yield a sanitized body-level 422 before field validation; measure that boundary before claiming it becomes a 500.
- Run long private-DB targets as tracked background jobs with pinned tool paths and exact-session readback. A foreground executor deadline can terminate the gate owner before its cleanup receipt, leaving an active synthetic fixture; never relabel this as cleanup or adopt/delete that historical fixture to force a green test.

## Optional consumers and cross-runtime admission

Keep optional catalog/source attestation out of ordinary DTO, API, supervisor and transport imports. A filesystem-only fingerprint reader can break ZIP-wheel startup even when source tests pass. Use operation-local imports or TYPE_CHECKING where appropriate, then test fresh no-opt-in imports and the real wheel factory; do not weaken the source reader to hide the coupling.

Before committing a durable reservation, compare the actual producer and runtime validators on identical independently resealed document bytes. Include lexical YAML forms, UTF-8 byte versus character limits, escaped controls, portable path rules and collection uniqueness. Keep the producer at least as restrictive as the consumer, preserve retained bytes, and prove refusal before writes/dispatch on a real qualified-publication PostgreSQL fixture. A downstream deterministic rejection must not become an unnecessary indeterminate reservation.

Include empty optional-looking prose and a leading BOM inside each authored scalar in producer/native parity controls, not only file-level UTF-8 checks. Requalify changed synthetic source through the real publication consumer and require zero durable reservations on deterministic refusal. Independently validate every nested Ref before Python equality: a correctly resealed `revision=true` can compare equal to `1` even when the enclosing envelope is valid; exercise the native pre-constructor boundary as well as the stricter producer.

Decode private JSON request bytes as strict UTF-8 before parsing and reject a leading BOM explicitly. Python's JSON byte-input autodetection can otherwise admit BOM or alternate encodings before a strict DTO sees the request. Pair the invalid-wire control with a valid request at the same pre-DB boundary, then prove the actual persistent consumer refuses without writes; do not change historical record payloads or silently normalize input.

Bound the same canonical RecordEnvelope on producer and native consumer, not only its scalar value and enclosing frame. JSON escaping and provenance/ref overhead can exceed the input-envelope cap while both other caps still pass. Test independently resealed API-origin material below/at/above that exact boundary, and require zero native constructors on refusal. Mirror canonical base64 round-trip checks as well as decoded schema hash/size checks: pad-bit aliases preserve decoded bytes but can create different accepted languages. Update the composer pin and attest the rebuilt installed bytes after a native guard changes.

Validate retained schema lexical bytes before JSON semantic parsing. CR is valid JSON whitespace but forbidden by the native LF/TAB-only document contract; parsing can discard that incompatibility. Compare independently resealed path/size/hash/package/base64 material, keep LF/TAB positive controls and CR/CRLF refusals, and reject before writes/qualification. Preserve raw bytes rather than normalizing them or widening historical accepted contracts.

## Verification
Acceptance includes valid/invalid input, concurrency, persistence/restart and schema compatibility. Record exact DB/Python versions and commands. Commit code, schema, tests and necessary docs as one coherent behavior change.
