# Omnis native Hermes integration

## When to Use
P2/P4/P7: supervisor, JSON-RPC, native children, providers/settings, skill snapshots, wake/stop/recovery. Do not replace Hermes with another agent framework.

## Prerequisites
Load the `hermes-agent` skill and relevant official documentation; read architecture §5 and the current integration gate. Check installed versus pinned Hermes revision using `terminal`. Use an isolated runtime home with synthetic test data, never the operator's personal profile, sessions, credentials or imported environment.

## Procedure
1. Declare the exact native contract being probed and its observable oracle. First build a deterministic protocol fixture; label it simulation. Then exercise the pinned real Hermes path inertly where possible. Provider inference is separately opt-in with explicit model/account/budget.
2. Implement one private supervisor owner. Parse protocol framing, request IDs and server-to-client requests; bound time/output and test EOF, cancellation and restart. Browser Omnis does not call management/RPC endpoints directly.
3. Establish task→native-child mapping BEFORE the first tool effect. Bind capabilities to trusted launch lineage and fencing epochs; a task ID in model text grants no rights. Test wrong-child, stale generation and cross-run substitution.
4. Pin executable skill content and every referenced file per RUN, not per task. Draft authoring is separate from runtime publication. Test unavailable tools, rejected bundles and emergency revocation through Stop/fencing.
5. Model native children as process-local, non-durable executions. Persist domain tasks, wake intentions, outcomes and recovery decisions in Omnis. ACK admitted/delivered/consumed are distinct; test crash at each boundary and duplicate wake without duplicate effects.
6. Verify Stop in two dimensions: no newly authorized target effects, and no unapproved model continuation. A 202 is STOPPING. Interrupt/cancel acknowledgements are not proof that children, auto-wake and executors are drained.
7. Keep Settings secrets out of prompts/logs, use save→readback for nonsensitive effective configuration, and freeze provider/model/catalog during a run. Probe 401/429/cancel/logout without calling them successful inference.
8. Record whether the installed API supplies each required capability. Prefer plugin contracts; use only a minimal audited upstream patch if unavoidable, with pin and regression tests. Missing support blocks the gate rather than motivating a FIFO/goal-text association.

## Pitfalls
Profiles are not OS sandboxes. Hooks/tool descriptions are not an egress boundary. A simulated RPC peer is not the real runtime; an installed skill is not a validated investigator. Keep the development MCP tools out of the assessment runtime.

- Keep Settings save and local authentication as separate observations: save returns NOT_VERIFIED, while auth_read produces the local grant state and still does not establish inference readiness. When the Host retains only the latest Settings operation, pass that operation_id through model_test_start/context/replay; a stale save ID cannot identify the later authentication read. Exercise the real consumer sequence with absent-grant and stale-ID controls rather than changing the producer to claim authentication.

- Trace an existing operation through every transport validator registry, not only its advertised RPC and final handler. Use the actual owner-produced payload and a positive through both gates: a missing registry entry can reject legitimate initialization while mocked owner tests pass. Preserve pre-client DATA/HOLD and require the real PG/native consumer before crediting constructor or persistence behavior.

- Prove cross-process authority revocation before the first cancellation/transport-finalizer await. A genuine HTTPcore trace veto can still read a stale native lease after the Host enters STOPPING; queuing SIGTERM does not prove its handler already ran. Exercise an otherwise-valid native send at that cleanup cut and preserve the admitted control, rather than obtaining denial from a missing new bootstrap prerequisite.
- Preserve the native terminal cause when cancellation or expiry overlaps transport failure. Joining a worker proves local settlement, not the outcome of a possibly sent request. Keep ambiguous errors INDETERMINATE, known pre-send cancellations distinct, and positively completed saves visible after Cancel; cancellation is neither logout nor upstream revocation.

- Attest live mounted state from the running container's mount namespace, not a Docker archive copy: `docker cp` may miss tmpfs contents. Use a finite, isolated installed-interpreter observer restricted to the exact synthetic paths; require unchanged file hashes and exact boolean marker absence, join the observer before family/drain checks, and retain a sensitive positive/negative control. Static installed source files can still be archive-attested separately.
- Renew actual stock-client authority immediately after successful launch, before blocking postlaunch census/observation; do not rely on a periodic task that has not yielded or extend the product grant to accommodate the harness. Register and checkpoint partial launch/renew/family evidence before an observer can refuse. A later successful run does not establish the cause of an older signal exit or reconcile its uncertainty.
- Keep credential-reader and native-runtime observation boundaries separate: an installed observer's store flags/modules and `/proc` initial environment do not prove the runtime's post-import memory, refresh behavior or loaded tools. Reverse `server_requests` advertisements are not a loaded-tool census. If a bootstrap registry is uninitialized/unobservable, retain NOT_INITIALIZED/NOT_OBSERVED rather than import/register/prewarm tools to fabricate an empty or complete inventory.
- Verify a proposed pre-run guard's actual veto semantics before using it as authority: the pinned `subagent_start` observer runs after child construction, omits an explicit batch index/manifest and swallows failures; execution middleware may fall through to downstream after an exception. Require an explicit indexed trusted sidecar and a fail-closed commit barrier before access, not association after `launch()` returns or a callback that merely logs failure.
- Establish NO_MODEL before native client initialization and conversation admission, not by cancelling a launched child, setting zero iterations or passing empty toolsets. At the pin, empty `allowed_toolsets` inherits the parent inventory. Keep installed preparation/loading evidence separate from native result/continuation evidence; neither a fake provider nor a deterministic emitter closes the latter boundary.
- Guard the public request entry before route selection, stale breakers and recovery, not only its worker constructor or shared sink: a stock pre-setup exception can otherwise escape NO_MODEL into credential/fallback handling. Keep a real open-breaker negative and the identical nonmanaged stock control; untrusted DTO refs and absence of an inert environment flag are not turn/config authority.
- Check exact inventory type before emptiness in a constructor-owned configuration observation: a nonempty tuple subclass can spoof equality with `()`. Require native tuple type before length, retain adversarial controls for both tools/toolsets, and never promote a genuine cold/null observation into READY provider-config or native-turn authority.
- Preflight effective non-root UID readability and directory searchability for every COPY artifact, including source, adapter, probe and manifest. Hash equality does not prove that imports can execute: preserve private modes with explicit owned COPY ownership rather than switching to root or loosening containment. Classify a pre-import permission exit as QA-driver BLOCKED/constructor NOT_RUN, retain that attempt and correct only owned distribution metadata before one bounded new consumer attempt; do not build another verifier.
- Trace a diagnostic launch seam through constructor-owned authority and final Stop predicates before using it in installed QA. `TestLaunch`/`TestPreparation` intentionally disable `namespace_owned` even at PID1; requiring certified STOPPED from that mode is unsatisfiable. Verify the actual caller and matching installed source; use the legitimate fixed-entry path rather than forcing the flag or weakening cleanup.
- Keep new diagnostic timer cancellation and each owned diagnostic FD close independently best-effort so observation cleanup cannot replace a primary exception or skip remaining cleanup. Separate pre-Stop process evidence from post-Stop signals; a signal first observed after Stop does not explain an earlier launch failure.
- Preserve the existing unified-patch framing, section order and unchanged sections when resealing a minimal native overlay; do not assume `diff --git` headers or regenerate unrelated context. Reconstruct only from attested post-inert originals, run `git apply --check` and apply in an owned copy, then compare the complete patched-file inventory and SHA values before publishing pin/manifest hashes. This keeps a distribution-only correction distinguishable from changed executable source.

## Document preparation through the existing owner

Route an inert preparation command through the supervisor's already-connected RuntimeClient; a second connection is not interchangeable with that owner. Isolate the fixed finite loader worker's home, cwd and environment before native import, without populating the active case's skills tree or relaxing CaseSlot archival rules. Native skill_view with preprocess=False still invokes readiness/load_env: distinguish an attempted read of the absent fresh-home .env from successful credential access. Measure cold installed loading before choosing a new operation's timeout, keep existing grants unchanged, and credit only document preparation—not an agent, TaskResult or completed turn.

## Cold admission and root lineage

- Guard import-time provider discovery as well as client construction. A native import can consult credential sources before an agent exists; exercise the installed pin in a fresh home and record attempted reads independently before a guard raises.
- Bind each staged batch to its original root object and immutable native/session IDs. Recheck that same live root under the registry lock before replay-as-admission and first release; a different live resolver root cannot revive pending children. Keep terminal receipt readback receive-only and separate from new authority.
- Keep finite deterministic method execution in a constructor-owned mode distinct from cold refusal and warm/model initialization. Trace import-time stock tool/plugin discovery even when the instance inventory is empty; exclude an unused stock-only helper only at the audited inert pin and preserve the ordinary nonmanaged control. A real method result does not certify an inference turn.
- Maintain the same real supervisor lease producer in a long disposable consumer probe rather than extending its TTL/grant or forging authority; DB heartbeat alone does not renew Host authority. Mirror the connected READY/MANAGEMENT runtime renewal of the existing supervisor, and stop renewal at done/Stop; never regrant an in-flight managed request or resurrect an expired Host. Precompute stable audit roots and profile only relevant Python events so observation does not dominate the immutable operation budget. Separate wrapper and implementation frames when counting one native invocation.
- Filter immutable code names/source before requesting frames in a cold-bootstrap observer. Under Python auditing, global `sys.setprofile` access to `frame.f_code` creates `object.__getattr__` fanout even for unrelated imports; use supported interpreter-local `sys.monitoring` events with fail-closed registration and preserve the original start/return evidence and thread controls. Reproduce event counts rather than a flaky elapsed-time threshold, and never enlarge the product grant to hide observer cost.
- Exercise repeated forbidden calls whose caller catches the observer exception. A raised `sys.setprofile` callback disables profiling, so one successful refusal does not prove later attempted effects remain observed; require independently retained attempt rows and zero forbidden-body entries across repeated/main-thread/new-thread controls. This is Python observer evidence, not OS confinement or a retrospective explanation of an older native failure.
- Retire an interrupted preobtained-grant exchange before leaving its held fence, preserving committed intent and the original exception without a second grant or resend. Test cancellation after actual writer drain on the real IPC stream. On Python 3.13, close active server clients before `Server.wait_closed`; prove exit, EOF, exact endpoint/lock cleanup and reuse on a live idle-client control.
- Compare a managed request's client exchange budget with every cold-start step it contains before attributing a handshake cancellation to native expiry. Exercise the actual client timeout→UDS close→Host EOF/cancel chain with a same-channel fast control and a downstream within-grant control; a valid grant does not prevent an earlier client timeout. Keep historical attribution UNKNOWN without its first-cancel evidence, and stop for authorization if the proposed remedy enlarges a limit or splits the authority/async contract.

## SDK-only preparation

- Treat extracted cache trees as insufficient provenance for original wheel hashes. Acquire only the explicitly granted lock URL/size/SHA closure, then install into a fresh private environment with offline, binary-only, hash-required copy mode; do not expand or update the closure.
- Check the pinned CLI grammar before consuming an installation intent: `uv pip sync` takes the requirements file positionally, not with `-r`. A parser refusal before installation is a QA-driver failure, not a product or SDK result; preserve it and reconcile the environment before a corrected distinct command.
- Exercise only the existing family runner's argument parser with the exact proposed argv before passing a namespace command containing standalone `--`. An embedded separator can be consumed by the outer argparse parser before the command starts; a missing family receipt remains UNCERTAIN. An exec-only argv wrapper may be proposed without replacing the owner or weakening isolation, but requires focused exact-snapshot review and real execution before credit.
- Keep full synthetic HTTP body bytes and request extensions when characterizing SDK serialization; digest/field-name output alone cannot show the model/messages/caps that were actually serialized. A capture-source stub proves driver retention only. No SDK execution means equality, extra_body behavior and namespace/seccomp controls are NOT_RUN, never inferred from installed metadata or static source.
- Stop after two QA-only repair cycles that do not answer the SDK question; hand off the concrete launch/consumer blocker rather than constructing a third audit. Record development-review traffic separately from forbidden product inference and verify leaf model/effort/Fast/approval settings before its first request rather than assuming delegate inheritance.

## Verification

- Put extra SDK QA source copies beneath an already declared read-only mount, and resolve every source import against the exact bwrap destination map before consuming the attempt. A hash-verified host copy outside all mounts is still unavailable inside the sandbox; repair only the owned mapping/path, never expose a broader home or relax confinement.
- Keep lazy SDK platform metadata separate from the serialization oracle when it attempts `uname -p`: first preserve the actual denied audit event and source stack, then use a precisely tagged stock metadata negative control under active confinement before any create. Retain every event and require zero additional serializer IO; do not patch SDK/platform, fabricate headers, or call a cached-metadata measurement zero attempted IO at cold-start.
- Supply absolute control paths for leaf reports. A relative `implementation/...` can land in the repository instead of the owner's deterministic control directory. Preserve the scope deviation and relocate only exact newly created reports with a registered inverse and byte/hash readback; do not delete unknown files or transfer approval to changed product bytes.
Each G02/G04/G07 subgate has evidence at its actual boundary. Test restart, compression/lineage, duplicate events, wrong identity, stopped run and bounded outputs. Report live LLM tests as not-run until explicitly authorized and exercised.
