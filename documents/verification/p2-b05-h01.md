## Execuție autorizată și ownership

Doi Dev leaf dețin doar scratch nou și disjunct: A pregătește Q2→Q3 installed NativePeer, B pregătește Q1 stock supervisor/PG. Fără schimbări de produs inventate pentru absența unei probe. Părintele integrează driverii exact, cere două reviewuri complementare pe același manifest înghețat și QA independentă pe consumatorul instalat. Un defect confirmat cere reproducer RED→GREEN, fix minimal, gate-uri afectate și re-review focalizat.

Buget finit: maximum o PostgreSQL disposable și trei runtime-uri noi, booturi explicite nereutilizate; provisioning120s, QA90s după fixture ready, rescue10s per namespace. Imaginea existentă poate fi refolosită numai după atestarea bytes instalați curenți; wheelul API este instalat într-un mediu privat nou și comparat cu sursele. Nu reutilizăm starea/fixture-urile vechi.

- **Q1:** stock supervisor instalat→InstanceService/PG real→RuntimeClient→UDS→RuntimeHost→Hermes pinuit. Un boot pozitiv nominal; alt boot pe același tip de canal: după READY, signal pe leader nativ exact→exit/stdout EOF→supervisor refuză runtime loss; drain/readback înaintea creditului de release. EOF+exit este un singur fault cauzal. Fără case-mode/A→B→A rerun.
- **Q2:** installed NativePeer standalone→nativ inert real într-un namespace propriu. Handshake/ping pozitiv→SIGSTOP exact→32 pending/al33-lea refuz→deadline-uri finite→CONT/ping valid pe același canal. Nu atribuie stock supervisor, PG sau watchdog acestei probe.
- **Q3:** același canal Q2, după ping valid: închiderea stdin de către părintele real→EOF nativ/transport→exit/reap bounded. Nu înlocuire de peer/read/drain, RPC nou sau metodă publică.

Helperii read-only sunt invocați explicit cu `python -I -B`; env-only PYTHONDONTWRITEBYTECODE nu este suficient cu -I. Ledgerul propriu fixează daemon/endpoint, inventarul foreign, roots/mounts/nonce/image/CIDs/process handles înainte de efecte. Părintele deține cleanupul final: join/CONT/rescue numai familia exact-owned, rm numai containerele proprii oprite și atestate, readback CID/socket/process/network/lease. Păstrăm PGDATA, starea sintetică, jurnalele, imaginile și FAIL/UNCERTAIN. Fără prune/DROP/reset/adopție/cleanup istoric. Git revert nu inversează efectele externe; reconstrucția cu date păstrate cere mandat separat, fără restart automat.
