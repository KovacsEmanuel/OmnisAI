## Next falsifiable boundary

Before integrating any owner module, require an **owned** transient Stop-only scope that (1) receives both original lifecycle lock FDs and an anonymous one-use admission channel, (2) starts the fixed child behind a pre-exec gate and pins it before effect, (3) proves a detached descendant remains inside the delegated scope and that cleanup reaches `cgroup.events: populated=0`, with a no-op kill and an unrelated process as negative controls, and (4) survives launcher death while retaining locks and writing only a verified receipt. Verify failure to create/delegate the scope leaves no effect and a durable `UNCERTAIN`/`RECOVERY_REQUIRED` locator; never infer daemon completion from the client exit or the cgroup alone. Only then attempt one typed real Docker CID stop with daemon ACK and exact readback on a new attested fixture. The current synthetic `stop_owner.py` branch is **not integrated** and was rejected by independent review for stale PREPARED replay and incomplete child/descendant cleanup. If an owner cannot prove these bounds, keep SL04 BLOCKED rather than letting a new process adopt an absent CID as an ACK.

No files in the user profile or historical recovery fixtures were modified, no push was made, and the transient test scopes exited. This spike does not change the S01–S07 frozen acceptance criteria or the separate M03/M22/G00 gates.
